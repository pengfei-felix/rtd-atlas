# Q-time 走廊的起点

<div class="keyline" markdown>

**走廊的起点不是一个时刻，是一个事件。** 清洗区之所以特殊，是因为全厂大部分走廊都从这里起算——它慢十分钟，后面三四个区全部少十分钟。

</div>

## 为什么起点在清洗

工艺路线的结构决定的：清洗通常紧跟在会产生"活性表面"的工序之后。

| 前道工序 | 清洗后暴露的表面 | 窗口紧迫度 |
|---|---|---|
| 刻蚀 / 去胶 | 新鲜图形侧壁 | 高 |
| 氧化 / 沉积前 | 裸硅或新生膜面 | **极高**（native oxide） |
| CMP 后 | 金属或介质表面 | 中高 |
| 注入后 | 受损表面 | 高 |

清洗完成的那一刻，表面从"受控"变成"暴露"，倒计时开始。

## 计时起点必须是事件

这是最容易出错的地方。三种做法，只有第二种是对的：

| 做法 | 问题 |
|---|---|
| 按计划时刻起算 | 实际晚开十分钟，窗口就少算了十分钟 |
| **按实际事件起算**（出槽、干燥完成） | 正确 |
| 各区自己起算 | 区间边界必然对不上 |

第二种要用机台事件，不是 MES 状态变更。某些设备的状态上报有延迟，用状态变更会晚几十秒到几分钟——对分钟级的窗口来说这是实质误差。

### 起点用"出槽"还是"干燥完成"

| 起点 | 适用 |
|---|---|
| 出槽（离开药液） | 化学腐蚀类窗口 |
| 干燥完成（可搬送） | 氧化类窗口，更严格 |

选哪个取决于窗口的物理机制。native oxide 类的窗口应按干燥完成算——湿膜状态下的氧化速率和干燥后不同。

## Native Oxide 窗口

这一类是清洗区最紧的约束：

| 条件 | 氧化层增长速度（量级参考） |
|---|---|
| 洁净室环境、室温 | 约 1 nm / 小时级（受湿度、洁净度影响） |
| 高温高湿 | 明显加快 |
| 有光照 | 加快 |

!!! warning "数字只作量级参考"
    具体速率随环境、晶圆表面状态、掺杂差异很大。这里的意义是说明**窗口是分钟到小时级，不是天级**，不能当成工艺规格引用。

工程含义：

- "清洗 → 沉积"这一段窗口经常是最短的；
- 这段时间里的每一分钟排队都在消耗预算；
- 所以清洗区的**出口**比入口更关键。

## 出口限流

清洗区最常见的错误优化是"提高清洗机利用率"。正确做法是反向的：**控制出口流量**。

| 策略 | 做法 | 效果 |
|---|---|---|
| 出口限流 | 后道接不住就不放行 | 避免 Lot 堵在出口，走廊计时白跑 |
| 下游预约 | 清洗前预约后道能力 | 出槽即有位置 |
| 分批出发 | 不追求一次全部出完 | 平滑下游负荷 |

出口限流听起来反直觉——明明能洗，为什么不让洗。理由很简单：**洗完了在那里等，和没洗没有区别，但走廊已经在计时了。** 提前洗等于把风险提前。

## 重洗与走廊

重洗会重置走廊吗？**不会。**

| 情况 | 走廊处理 |
|---|---|
| 正常清洗完成 | 从出槽重新计时 |
| 重洗（未离开该工序） | 走廊不重置，仍按原起点 |
| 返工（工序已完成，返回重做） | 按新的工艺路径重新建走廊 |

第二条要写进规则。重洗被当成新起点，等于给了无限次延长窗口的机会——现场很快就会发现这个漏洞。

## 典型问题

### 问题 1：起点用状态变更，误差几分钟

| 项 | 内容 |
|---|---|
| 现象 | 系统显示还有 20 分钟，实际只剩 12 分钟 |
| 根因 | 用 MES 状态而不是机台事件计时 |
| 解法 | 接机台出片事件，纳秒级时间戳 |
| 指标 | 起点时间偏差分布 |

### 问题 2：为提利用率提前洗

| 项 | 内容 |
|---|---|
| 现象 | 清洗利用率高，下游堵，走廊 breach 上升 |
| 根因 | 目标函数只看本区吞吐 |
| 解法 | 出口限流 + 下游预约 |
| 指标 | clean-out wait、batch-induced breach |

### 问题 3：重洗被当新起点

| 项 | 内容 |
|---|---|
| 现象 | 反复重洗把窗口无限延长，最后超时 |
| 根因 | 走廊在重洗时重置 |
| 解法 | 重洗不重置走廊，按原起点 |
| 指标 | re-clean count、re-clean 后 breach 率 |

### 问题 4：干燥能力不足造成的假完成

| 项 | 内容 |
|---|---|
| 现象 | 系统认为清洗完成，实际干燥还在排队 |
| 根因 | 干燥不作为独立步骤，或者完成事件定义错 |
| 解法 | 干燥建为独立资源，完成事件在干燥后 |
| 指标 | dry wait、起点定义偏差 |

## 一条实操建议

把清洗区当成**走廊的入口闸机**来设计，而不是当成一个加工区来优化。

具体做法：清洗区的派工目标写两条，第一条是"不许让任何走廊 breach"，第二条才是"最大化处理量"。顺序不能反。
