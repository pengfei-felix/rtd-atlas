# Sorter / Stocker 派工档案

<div class="keyline" markdown>

**这是全厂唯一一个决策粒度是"载具"而不是"机台"的区。** 派工要回答的不是"这批料上哪台机"，是"这批料进哪个 FOUP、放在哪个格子、允不允许和别的料挨着"。

</div>

## 核心结论

1. **载具是独占资源，而且数量有限。** FOUP 不够，机台再空也跑不起来——这类假性 idle 在报表上看起来像设备问题。
2. **污染分区是硬约束。** Stocker 按污染等级分区，放错格子等于交叉污染。
3. **Sorter 是 Lot 与载具解耦的地方。** 合批、拆批、换载具都发生在这里，直接影响后续派工自由度。
4. **8 寸和 12 寸差一个量级。** 12 寸是 OHT + Stocker 网络，8 寸大量是人手暂存区。
5. **它不加工，但它能让全厂停摆。** 判断标准不是吞吐，是"卡住的时候有多严重"。

<div class="rtd-strip" markdown>

<span>决策粒度</span> Lot → Carrier → Slot / Port  
<span>核心矛盾</span> 载具利用率 vs 污染隔离 vs WIP 流转

</div>

## 为什么它算一个区

严格说它不是工艺区。放在区域分幅里，理由是三条：

| 理由 | 说明 |
|---|---|
| 有独立的约束结构 | 载具池、slot、污染分区，和加工区完全不同 |
| 有自己的决策变量 | 载具分配、分选、暂存位置 |
| 会独立造成停摆 | 载具不足、stocker 满、分区冲突，都会让派工失效 |

如果只按"有没有工艺加工"来划分，它会被漏掉——而漏掉它的代价是：计划全部可行，现场因为没 FOUP 一动不动。

## 与加工区的结构差异

| 维度 | 加工区 | Sorter / Stocker |
|---|---|---|
| 决策粒度 | Lot / Chamber / Batch | **Carrier** |
| 加工对象 | 晶圆 | 载具 |
| 加工结果 | 状态改变 | **位置或归属改变** |
| 独占资源 | 机台、腔体 | **载具、slot、port** |
| 失败后果 | 返工 / 报废 | 延误、污染、混料 |
| 优化目标 | 吞吐、周期 | 流转顺畅、载具周转 |

## 六类约束结构

### 1. 载具池

| 字段 | 说明 |
|---|---|
| `carrier_id` | 唯一标识 |
| `carrier_type` | FOUP / Cassette，slot 数、尺寸 |
| `contamination_class` | 与污染矩阵同口径 |
| `current_location` | 机台 / stocker / 搬送中 |
| `assigned_lot` | 当前装载的 Lot |
| `clean_due` | 下次清洗时刻 |

三条规则：

1. **载具随 Lot 走，不随区走。** 载具卡在某区，等于把 WIP 卡在那。
2. **污染等级跟载具，不跟 Lot。** 换载具必须重新判定。
3. **预留优先于即时分配。** 走廊预留的载具不能被常规派工抢。

### 2. Slot 与 Port

| 资源 | 约束 |
|---|---|
| Stocker slot | 按分区、按载具类型，数量固定 |
| 机台 port | 每台机 1~4 个，占满即不能收料 |
| Sorter port | 进出分开，同时占用 |
| 缓冲位 | 临时占用，需要释放规则 |

**Port 占满是"看起来空闲但其实不能上料"的典型原因。** 机台 idle、有料、就是进不去。

### 3. 污染分区

Stocker 分区和机台分区是两套，必须一致：

| 分区 | 存放什么 | 冲突后果 |
|---|---|---|
| Cu 区 | 铜工艺载具 | 与 non-Cu 混放即污染 |
| Non-Cu 区 | 常规载具 | — |
| 待清洗区 | 用过的载具 | 不能与洁净载具相邻 |
| 工程 / 特殊 | 特殊批次 | 按产品要求隔离 |

**载具从 Cu 区搬到 Non-Cu 区之前必须清洗。** 这条规则缺失，Stocker 会成为污染的传播节点。

### 4. Sorter 的分选逻辑

Sorter 做三件事：

| 动作 | 目的 | 对派工的影响 |
|---|---|---|
| 合批 | 把多个小批合成一个载具 | 提高后续批量性，利于批式机台 |
| 拆批 | 把一批拆到多个载具 | 提高并行度，但增加载具占用 |
| 换载具 | 因污染或维护更换 | 重新判定污染等级 |

**合批拆批是派工自由度的来源。** 提前合批，后续可以上批式机台；拆批能并行但吃载具。这个决策通常由计划做，但 RTD 要知道当前载具的构成。

### 5. 与 AMHS 的边界

| 环节 | 归谁 |
|---|---|
| 载具存取位置 | Stocker / Sorter（本区） |
| 载具搬运 | AMHS / MCS |
| 搬运优先级 | RTD 提出，MCS 执行 |
| ETA 计算 | MCS |

边界要说清楚，否则会出现两套优先级打架。详见 [AMHS/MCS 联动](../topics/amhs-mcs-coupling.md)。

### 6. 8 寸的特殊性

| 项 | 12 寸 | 8 寸 |
|---|---|---|
| 搬送 | OHT 全自动 | 人工 + AGV 混行 |
| 暂存 | Stocker 网络 | 多有临时暂存区，无系统管理 |
| 载具 | FOUP，标准化 | Cassette，规格杂 |
| 状态可见性 | 高 | **低，很多位置系统不知道** |

8 寸的难点不是约束多，而是**状态看不见**。载具被放在暂存架上，系统里显示"搬送中"已经两小时——这种情况在 8 寸是常态。

对策：至少把"最后一次已知位置 + 时间"建模，超过阈值触发寻料，而不是假装状态是准的。

## 典型派工问题

### 问题 1：假性 idle

| 项 | 内容 |
|---|---|
| 现象 | 机台空闲，有料，就是上不去 |
| 根因 | 载具不足或 port 占满，不在资源视图里 |
| 解法 | 载具池和 port 状态进 RTD |
| 指标 | false idle rate、carrier wait |

### 问题 2：载具污染等级没更新

| 项 | 内容 |
|---|---|
| 现象 | 干净载具被派去装铜工艺片 |
| 根因 | 载具换装后未重判污染等级 |
| 解法 | 载具污染等级独立维护，换装即重判 |
| 指标 | carrier contamination mismatch |

### 问题 3：Stocker 分区满了导致绕行

| 项 | 内容 |
|---|---|
| 现象 | 附近 stocker 满，载具要搬到远处 |
| 根因 | 分区容量不均衡，且不在派工约束里 |
| 解法 | 分区容量进视图，超阈值提前均衡 |
| 指标 | stocker utilization variance、搬送距离 |

### 问题 4：8 寸状态丢失

| 项 | 内容 |
|---|---|
| 现象 | 系统显示搬送中，实际放在某处没人动 |
| 根因 | 人工暂存区不在系统里 |
| 解法 | 最后已知位置 + 时间，超阈值触发寻料 |
| 指标 | state unknown duration、寻料事件数 |

## 派工规则骨架

```text
当有 Lot 需要进出载具或暂存：
  1. 确定 Lot 的污染等级
  2. 过滤可用载具：类型匹配、污染等级匹配、清洁状态有效
  3. 检查目标位置：stocker 分区、slot 可用、port 未占满
  4. 检查搬送可行性：AMHS 是否可达、ETA
  5. 若为走廊预留的载具 → 不可被常规派工占用
  6. 分配载具与位置，写回状态
  7. 8 寸：记录最后已知位置与时刻，超阈值触发寻料
```

## 指标体系

| 层级 | 指标 | 用途 |
|---|---|---|
| 主指标 | 载具周转率、进出成功率 | 看流转是否顺畅 |
| 约束指标 | 污染错配、stocker 分区超限、false idle | 防止靠冒险提流转速度 |
| 观测指标 | 载具占用分布、搬运距离、状态未知时长 | 定位约束来源 |

## 落地路线

1. **先把载具池接进系统**：这是所有后续工作的基础，也最容易见效。
2. **再接 port 与 stocker 容量**：消掉假性 idle。
3. **然后做污染分区匹配**：纯过滤规则，防事故。
4. **最后做分选优化**：合批拆批的策略，收益最小但最复杂。
5. 8 寸单独处理：先解决"状态看不见"，再谈优化。
