# 载具池与污染分区

<div class="keyline" markdown>

**载具是 Fab 里最典型的"谁都在用、没人负责"的资源。** 它不出现在设备清单里，不占用工艺产能，但少一个就能让一台机停在那里。

</div>

## 一张载具池台账

| 字段 | 必须 | 说明 |
|---|---|---|
| `carrier_id` | 是 | 唯一位号 |
| `carrier_type` | 是 | FOUP 25 slot / Cassette 25 slot / 特殊规格 |
| `contamination_class` | 是 | 与污染矩阵同口径 |
| `current_location` | 是 | 机台 / stocker 分区 / 搬送中 / 未知 |
| `location_timestamp` | 是 | 位置更新时刻，用于判定状态可信度 |
| `assigned_lot` | 否 | 当前装载 |
| `slot_usage` | 是 | 已用 / 总数，用于判断能否合批 |
| `clean_due` | 是 | 下次清洗时刻 |
| `reserved_for` | 否 | 预留给哪条走廊或哪个批次 |

`location_timestamp` 这一列在 8 寸尤其重要，后面会讲。

## 载具的三个状态维度

载具不是"可用/不可用"二值，是三个维度交叉：

| 维度 | 取值 | 影响 |
|---|---|---|
| **物理状态** | 正常 / 待清洗 / 维修中 / 报废 | 能不能用 |
| **污染等级** | Cu / Non-Cu / 金属 / 洁净 | 能装什么 |
| **位置与可用性** | 在库 / 在机台 / 搬送中 / 未知 | 什么时候能用 |

只有三维都满足，才是真可用。只看"在库"就派，会派到污染等级不符的载具上。

## 污染分区的三套规则

### 规则一：载具跟等级，不跟产品

同样一台机，装铜工艺片的载具不能去装 non-Cu 片，即使 Lot 本身"看起来没问题"。

污染等级在**载具更换时**重判，不是在 Lot 变更时。这条经常配反。

### 规则二：分区之间要清洗才能跨

| 移动 | 是否需要清洗 |
|---|---|
| 同分区内移动 | 否 |
| Cu → Non-Cu | **必须** |
| 待清洗区 → 任何生产区 | **必须** |
| 工程区 → 生产区 | 按产品要求 |

清洗本身占用产能，所以跨区移动有成本。做载具均衡时要算这笔账，不能只算搬送距离。

### 规则三：Stocker 分区容量要均衡

| 现象 | 原因 | 后果 |
|---|---|---|
| 某分区长期满载 | 产能分布不均 | 载具被迫搬到远处 |
| 某分区长期空置 | 产品结构变化 | 空间浪费，搬送距离增加 |
| 分区边界模糊 | 规则没定义 | 现场自行判断，逐步失效 |

第一条最常见：铜工艺产能扩张后，Cu 区不够用，但分区调整要走变更流程，于是长期靠"临时放一下"维持——临时状态最后变成事实标准。

## 合批与拆批

这两个动作直接改变后续派工的自由度。

| 动作 | 好处 | 代价 |
|---|---|---|
| **合批** | 后续可上批式机台，提高装载率 | 载具占用增加，灵活性下降 |
| **拆批** | 并行度提高，缩短单批周期 | 吃载具，增加机台 setup 次数 |
| 保持原样 | 无额外代价 | 可能错过批式机会 |

### 判断依据

```text
如果 后续工序中有批式机台，且合批后能显著提高装载率
   → 合批
如果 后续全是单片机台，且批次已进入紧走廊
   → 拆批并行
否则
   → 保持原样
```

关键在"后续有没有批式机台"。漫无目的地合批，只是把载具锁死。

## 8 寸：状态看不见怎么办

这是 8 寸最真实的问题。人工搬送、临时暂存架、口头交接，导致系统状态长期不可信。

### 不要假装状态是准的

错的做法的：默认位置准确，超时才发现不对。
对的做法：**显式建模"可信度"**。

| 状态 | 判定 | 处理 |
|---|---|---|
| 可信 | 刚有事件更新，< 阈值 | 正常使用 |
| 存疑 | 超过阈值未更新 | 派工前先确认 |
| 未知 | 远超阈值 | 触发寻料，不参与派工 |

阈值按实际搬送节拍定，通常 30~60 分钟。

### 寻料流程

| 步骤 | 动作 |
|---|---|
| 1 | 系统标记"未知"，从可用池中摘除 |
| 2 | 通知现场按最后已知位置查找 |
| 3 | 找到后更新位置；找不到走丢失流程 |
| 4 | 记录事件，用于改进暂存管理 |

第 4 步是长期价值所在。寻料事件高发的位置，就是需要装读卡器或划固定暂存区的地方。

## 典型问题

### 问题 1：载具换装后污染等级没重判

| 项 | 内容 |
|---|---|
| 现象 | 干净载具装了铜工艺片，下一批 non-Cu 污染 |
| 根因 | 污染等级绑在 Lot 上而不是载具上 |
| 解法 | 载具独立维护等级，换装即重判 |
| 指标 | carrier contamination mismatch |

### 问题 2：跨区搬送没算清洗成本

| 项 | 内容 |
|---|---|
| 现象 | 载具均衡方案看起来很好，实际执行慢 |
| 根因 | 只算搬送距离，没算清洗占用 |
| 解法 | 跨区移动的成本包含清洗时间和产能 |
| 指标 | carrier cycle time、clean wait |

### 问题 3：Stocker 分区靠临时方案维持

| 项 | 内容 |
|---|---|
| 现象 | 分区规则写着 4 个区，实际用了 5 个位置 |
| 根因 | 容量不足但变更流程太长 |
| 解法 | 定期评估分区容量，把临时方案纳入正式配置 |
| 指标 | 非规划位置使用率 |

### 问题 4：8 寸寻料频繁

| 项 | 内容 |
|---|---|
| 现象 | 每天多次找不到载具 |
| 根因 | 暂存区无系统管理 |
| 解法 | 先做状态可信度建模，再按热点加管控点 |
| 指标 | state unknown duration、寻料次数 |

## 一条实操建议

**把载具数量当成一个产能约束来做规划，而不是当成物料管理。**

问一个问题：如果所有在制批同时需要载具，够不够？

多数 Fab 的答案是不够的，但因为平时不同时需要，所以从来不觉得缺。一旦出现批量返工、集中出货、或者分区调整，载具立刻成为瓶颈。

算出"峰值载具需求 / 实际载具数"这个比值。低于 1.2 就该补了。
