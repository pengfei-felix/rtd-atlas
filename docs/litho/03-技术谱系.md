# 解决方案技术谱系

按成熟度分层，**不要跳级**。跳级的典型后果是：算法上线但现场不信、人工干预率反而上升。

| 级别 | 方法 | 核心机制 | 数据/基础前提 | 收益量级 | 适用阶段 |
|---|---|---|---|---|---|
| **L0** | 静态优先级 + FIFO/SPT/EDD | 单因子排序 | MES 基础数据 | 基线 | 新厂通线期 |
| **L1** | **多因子加权派工公式**（PADR 类） | 权重 + 门槛值综合排序，含光罩/温层/Q-time/负载因子 | 整定时间矩阵、Dedication 表、Q-time 配置 | 明显优于 FIFO/SPT | 爬坡期（**国产厂主战场**） |
| **L2** | **预测型前瞻派工** | WIP 到达预测 + Reticle 预分配，提前 5~15 分钟锁产能 | 可靠的 WIP 预测、ARHS 运力模型 | 显著削减白空间 | 多产品混线期 |
| **L3** | **短周期优化排程（SIS）+ RTD 执行** | 每数分钟产一次局部最优排程，由 RTD 实时微调执行 | 离散事件仿真能力、归一化数据模型 | Litho 利用率 **>+1%**，吞吐 **+2.1%**（AMAT 公开） | 成熟量产 |
| **L4** | **MILP / CP 数学优化** | 精确建模全部硬约束，求最优/近优 | 高质量参数（按机台×罩配对统计的加工时间分布、故障分布） | 相对启发式**额外 +3~5% 吞吐**（AMAT 口径）；Photo 区 **+9.4% 吞吐**（Flexciton/Seagate） | 瓶颈区专项 |
| **L5** | **RL / AI 自学策略** | 从历史调度数据学最优策略，替代人写规则 | 大量带标注的历史决策数据 + 数字孪生验证环境 | 行业在研，公开实证有限 | 前瞻投入 |

### L3 的标准架构（AMAT SmartSched 三件套，值得照搬）

```
[1] 实时数据生成与准备
    从 MES / 其他自动化系统导入明细 → 构建归一化的详细数据模型
         ↓
[2] 基于仿真的预测
    全厂离散事件仿真 → 预测 WIP 及其到达特定工步的时间
    输入：WIP 量、设备状态、计划 PM、产品组合、负载
         ↓
[3] 局部优化短周期排程
    输入：厂状态详细模型 + 预测到达时间 + 上一版排程
    用实时数据构造 Litho 场景约束 → 收窄解空间 → 生成多个候选排程
    目标函数（可配权重）：CT / 工步交期 / Move 目标 / Reticle 移动数 / 稳定性
         ↓
输出：Lot-机台分配 + Lot 加工顺序 + Lot 与 Reticle 搬送指令 + Reticle 检查排程
         ↓
[4] RTD 执行层：秒级按实时状态微调，偏差超阈值时推翻计划
```

**三个设计要点**：
- **"稳定性"必须是目标函数的一项**。用户需要量化"减少排程变动"与其他目标的权衡——排程每次都大改，现场就不信了。
- 输出必须包含**搬送指令**，否则排程在物理上落不了地。
- **预测的价值是"把未来变成当前约束"**：提前知道 WIP 和 Reticle 将在哪里，才能避免把罩锁死在柔性高的机台上。

### L4 的关键工程手法：Reticle Move 与 CT 的"交换比"

Flexciton 的做法极具工程价值，建议**直接移植到 L1/L2 的权重设计中**——核心是把权重定义成**可解释的交换比**，而不是无意义的魔数：

> 设置 `TWCT : Reticle Move = 100 : 75`，含义是：**只有当避免一次搬罩所带来的加权总周期时间增加 ≤ 0.75 小时时，才选择避免这次搬罩。**

实测对比（6 机台 / 48 片 / 4 张罩 / 单机最大批 4 片）：

| 场景 | Reticle 移动次数 | TWCT（48 工步加权） |
|---|---|---|
| 只优化 CT，不惩罚搬罩 | 7 次 | 16.79 h |
| 中等惩罚搬罩（100:75） | **5 次（-28%）** | 18.73 h（+11.6%） |

**可直接用的三条启示**：
1. **把所有权重改写成"交换比"**。`w2 = 0.75 h/次搬罩` 这种定义工程师能讨论、能评审、能和产线谈判；`w2 = 0.3` 没人知道什么意思。
2. **搬罩惩罚不只是时间成本，还有光罩损伤风险成本**。Flexciton 明确提到"潜在损伤风险被认为更高"——这是时间模型里没有的隐性成本，必须显式加进去。
3. 中等惩罚下引擎的行为变化很有启发：**宁愿等低优先级批到达后与高优先级批连跑，也不多搬一次罩**。这正是人工派工想不到、但事后看完全合理的决策。

### Seagate 实测：三指标同时改善的存在性证明

Flexciton 在 Seagate 光刻区（**1600 工步的高重入流程**）单机群实测、真实量产环境、机台内置光罩库、罩可在机台与柜间单独移动：

| 指标 | 结果 |
|---|---|
| 吞吐量 | **+9.4%** |
| Reticle 移动 | **−5.3%** |
| Queue Time | **−4.3%** |

> 这组数据的价值在于**打破"吞吐与搬罩必须权衡"的直觉**。吞吐涨了 9.4% 而搬罩反而降了 5.3%，说明原有的启发式派工在解空间里离最优点很远——**存在大量"又多搬罩又没多产出"的纯浪费决策**。这正是上优化引擎的核心论据。

### 工作负载均衡的轻量解法（EDA + K-means）

针对"光刻机工作负载不均"的专项问题，有一条比全局优化轻得多的路线：

- **按 Pattern Precision 分机台组**，精度数 = 机台组数，Group-g 能处理的最高精度为 Precision-g（高精度组可降级跑低精度活）。
- **把"同罩的所有待加工晶圆"聚合为一个 Job**（`O_au` = 精度 a + 罩 u），天然避免换罩 —— **这个建模技巧很值得学：把"减少换罩"从目标约束变成了问题定义本身。**
- 目标：`min (最长机台工时 − 最短机台工时)`。
- 用 **EDA（分布估计算法）+ K-means 聚类** 求解。

**适用判断**：当你的主要痛点是"负载不均 + 换罩过多"而非"交期与 Q-time 冲突"时，这条路线实施成本远低于 MILP/CP，效果直接。
