# 厂商方案横评

!!! note "范围说明"
    本页是**光刻专项**的深度横评，技术细节最全。跨区域的抽象版本见 [厂商与选型](../vendor/index.md)——那一组回答的是「这套能力能不能换个区用」，本页回答的是「在光刻区它到底做到了哪一步」。

### 4.1 国际阵营

#### Applied Materials（应用材料）—— APF RTD + SmartSched / SmartFactory

**市场地位**：RTD 市占率最高，存储厂近乎标配，与 AMAT 自家 MES/EAP 深度绑定。

**产品分层（这是全行业最清晰的分层定义，建议作为内部术语标准）**：

| 层 | 职能 | 时间粒度 | 生成频率 |
|---|---|---|---|
| Planning | 计划 | 周~月 | 低频 |
| **Scheduling（排程）** | **Lot 分配**：基于当前与预测的 Lot 到达、当前与未来设备状况，把 Lot 分配给特定区域的设备组 | 12 小时班次 | **10~15 分钟** |
| **Dispatching（派工）** | **Lot 排序**：特定设备上实时的 Lot 加工顺序 | 秒级 | 实时 |

- 全厂实施派工规则，分 **Global Rule**（含线平衡逻辑，管客户承诺）与 **Local Rule**（针对 Litho 等区域的吞吐优化附加逻辑）。
- AMAT 自己的定位表述很精准：**其派工方案可视为"实时排程"，而排程方案是"准实时排程"**。

**Litho 专项能力（SmartSched）**：
- 三件套架构（见上文 L3）；明确解决 **Reticle 未就位造成的白空间**。
- **关键机制**：前瞻避免"把 Reticle 锁死在一台机上，而另一台柔性更低、用同一张罩的机台即将空闲"。
- 输出含 Lot-机台分配、加工顺序、**Lot 与 Reticle 搬送指令、Reticle 检查排程**。
- 目标函数可配：CT / 工步交期 / Move 目标 / **Reticle 移动数** / **稳定性**。

**公开成效**：
- Litho 利用率 **>+1%**，Litho 出片 **+2%以上**，某产线光刻模块吞吐 **+2.1%**。
- 派工方案整体 **吞吐 +5~10%**；再叠加排程与派工集成 **额外 +3~5% 生产力**。
- 优化型排程相对启发式排程**额外 +3~5% 吞吐**（Infineon 案例背书）。
- 214 组产线数据对比纯启发式 RTD：**最高优先级批 CT 改善 ~20%，次高 <5%，低优先级不变**。

**短板**：
- 与 AMAT 自家 CIM 栈绑定深，混栈集成成本高。
- 公开数据多为 2011 年前后的 SmartSched 初代成效，**基线是当年的纯启发式 RTD**，不宜直接对标今天的优化引擎。
- 价格与本地化服务响应是国内客户的主要抱怨点。

**可借鉴的三件事**：① Planning/Scheduling/Dispatching 的三层术语与频率设计；② "稳定性"进目标函数；③ 排程输出必须包含搬送指令与检查排程。

#### Flexciton —— 纯优化路线的代表（Litho 专项实证最硬）

**技术路线**：数学优化为核心 + AI 增强 + **智能分解（smart decomposition）**。不靠规则，目标变了自己重找解——官方口径是"无需工业工程师写初始规则、也无需持续改规则"。

**产品分层**：
- **Flex Planner**：动态产能建模 + 数学优化 → 日投片计划，**每 45 分钟更新一次**。
- **Flex Local**：本地机群排程器，自主平衡组批/CT/吞吐，**无需调参或调规则**。
- **Flex Global**：连接各本地排程器，优化"正确 WIP 的到达"，消除 Timelink 违规、规划最优 Campaign。

> **Global/Local 分层很值得学**：Local 解局部最优，Global 负责"把对的 WIP 在对的时间送到对的 Local"。这恰好对应"重入流下局部最优 ≠ 全局最优"的根本困境。

**公开成效**：

| 场景 | 指标 |
|---|---|
| Photo 区（Seagate，1600 工步，量产实测） | 吞吐 **+9.4%**，Reticle Move **−5.3%**，Queue Time **−4.3%** |
| 扩散区（Renesas，仿真复现量产环境） | Timelink 违规 **−29%** |
| 扩散区组批 | 批量 **+18%** |
| 排程整体 | 全厂吞吐 **+6~8%** |
| 计划层 | 同等 WIP 水平下 CT **−10%**；目标速度标准差 **−30%** |

**规模与可信度**：25+ 个晶圆厂优化项目（美/欧/亚），40 名专注晶圆厂优化的专家，3 项数学优化专利；客户含 Seagate、Renesas、Microchip。部署周期 **6~12 个月**。

**短板**：
- 专注排程/计划，**不是完整 CIM 栈**，必须与既有 MES/RTD 集成。
- 优化引擎的**可解释性**是现场接受度的主要障碍（规则能讲清"为什么这批先做"，优化解不能）。
- 对数据质量要求高：参数不准，优化解就是"精确的错"。

#### 其他国际玩家

| 厂商 | 定位 | Litho 相关要点 |
|---|---|---|
| **IBM SiView** | 逻辑厂偏多，排程能力强 | 早期的 Litho 优化建模（US7151972B2 / US7653451B2）与**自动光罩管理**（US7953507）专利体系最完整：Lot 与 Reticle 在机台的**同时协同分配**、WIP 水位超动态阈值时**自动从"快速规则派工"切换到优化模型**。这个"规则↔优化自动切换"的思路非常务实——**平衡态用规则（快、抓实时信息），拥塞态用优化（慢、但要全局最优）** |
| **Brooks（RTS）** | 偏物流调度 | AMHS 集成度高。Litho 的 Reticle/Pod/FOUP 三类搬送耦合场景是其强项 |
| **日系** | 部分日资厂自研 | 不外售，可参考性低 |

### 4.2 国产阵营

#### 赛美特（Semi-Tech）—— PlantU 全栈，RTD + APS 双轨

**产品**：PlantU RTD（实时决策系统）+ PlantU APS（高级计划与排程），全栈含 MES / EAP / RMS / MCS / SPC / YMS / FDC / APC / AMS / SCADA / DT 等数十模块。

**PlantU RTD 官方能力**：面向 8"/12" 晶圆厂，综合 WIP、瓶颈、机台状态**实时生成最优作业顺序**。四项产品特性：
- **实时处理**：内置引擎与算法，即时出派工结果
- **易开发**：**拖拉拽 UI** 构建业务逻辑
- **灵活复用**：**宏模块（macro block）** 快速建规则、高复用
- **稳定架构**：成熟设计 + 健壮容错

> **宏模块 + 拖拉拽**这条路线是对"规则库膨胀"问题的直接应答——把 200 条 Rule 中的共性逻辑抽成可复用模块，维护成本大幅下降。**这是国产厂商相对务实且正确的选择。**

**AI 方向（2025-05 发布"AI 智造"体系）**：APS + RTD 动态优化生产节奏，订单优先级动态调整、机台负载实时平衡。技术路线是**用强化学习从历史调度数据自动提取最优策略**——从"人写规则"转向"机器学规则"。

**技术指标承诺（四川省揭榜挂帅榜单公开信息，可作为国产 CIM 能力基线参考）**：
- 支持生产调度自动化、工艺调优、**光刻板（Reticle）管理**、OCAP 流程化
- 高级集成生产控制：暖机控制、预测模型调优、**Wafer 级工艺调优**、10Hz 级生产监控、**Dual Reticle**、N2 Purge、NPW 管理、RunCard 管理
- 全模块实施达 **Auto3** 水平；支持 **25000 片/月** 产能性能要求
- 采购成本相对国外**下降 30%~40%**；已用于国内外 **100+ 家** 3/4/6/8/12" 工厂

> ⚠️ **注意两处**：① "Dual Reticle"被单列为高级集成能力——说明双罩场景在国产方案里仍属进阶项而非标配；② **25000 片/月**的性能指标对一座月产数万至十万片的 12" 大厂而言是明显的量级差距，选型时必须压测真实产能下的决策延迟。

**短板**：Litho 区的 Reticle 协同派工细节、公开的量化成效数据缺失；AI 路线对外发布早于成熟度（2025 发布，实证待观察）。

#### 上扬软件（FA Software）—— 国产 RTD 案例积累最深

**定位**：成立 25 年（2001），**股东含国家大基金与华为**，国资背景清晰。200+ 家行业客户，覆盖半导体/光伏/LED；**8" 晶圆厂市占领先**；单一客户最长服务 **>20 年**。

**产品**：全自研 CIM 全家桶 —— MES / EAP / SPC / RMS / APC / FDC / YMS / **RTD** / RCM / DMS / 数据仓库。旗舰 **myCIM 4.0** 面向 12"，**2022 年在豪威半导体 12" OCF Fab 落地**（国产 12" MES 的重要实践案例）。

**RTD 定位（官方口径最硬的一家）**：明确把 RTD 称为**"技术制高点""核心技术壁垒"**，并直言：
> "评估一套 CIM 系统的真实水平，MES 各家产品的差距相对有限，**RTD 的技术深度才是真正拉开差距的关键**。"
> "部分国内 CIM 供应商目前尚不具备 RTD 产品，这意味着其在高端晶圆厂的整体解决方案能力存在**结构性缺口**。"

其对问题难度的表述也最准确：柔性作业车间 + 重入工艺 + 驻留时间约束的强 NP 难问题，规模越大难度指数上升；RTD 需毫秒级决策；**每提升 1% 设备利用率即带来显著年产出增量**。

**核心优势主张**：**不是算法，是量产沉淀的工业知识**——"真实产线的工艺认知、设备特性与调度规则，无法通过短期研发复制"。

**AI 态度**：已在内部推进 AI 与 CIM 结合，**处于研发与内部测试阶段，技术成熟后才对外呈现**。明确区别于"把 AI 当营销概念优先推广"的做法。

**短板**：
- 优势集中在 8"，12" 案例数量相对有限（豪威 OCF 是主力背书）。
- **全自研同源**是优点（接口/协议/逻辑统一，免跨厂商适配）也是风险（单一供应商依赖、技术路线锁定）。
- Litho 专项的公开技术细节与量化成效披露最少——**这是尽调时必须重点追问的部分**。

#### 朋熙半导体（PXSemi）—— ARTD + RTFO 双产品线，IPO 进程中

**定位**：2019 年成立，600+ 员工、其中研发 500+；创始人彭海荣控股 46.4%；**2026 年 2 月已启动 IPO 辅导**（国泰海通保荐）。主打 12" 晶圆厂 CIM 整体方案设计与现场建设。

**派工相关产品线（分得最细的一家）**：

| 产品 | 定位 | 官方能力描述 |
|---|---|---|
| **ARTD** 实时工厂排程系统 | 旗舰 | **全局优化**多客户/多产品/多任务/多周期；开放标准架构；**成熟可靠的规则库 + Fab 排产模型（WIP 及 CT 优化）**；国产化**内存数据库**设计 |
| **AFPO** 实时工厂排程系统 | 产能层 | 最大化产能、最小化成本、优化产品配置计划、**最佳 batch & OTD** |
| **RTD** 实时调度系统 | 执行层 | 实时动态调度；提升 OEE、减少设备空闲率；优化人工决策过程 |
| **SDR** 自动派工 | 事件层 | **实时感知工厂事件 → 启动决策响应 → 运行预定义决策流程 → 与外部系统交互执行决策** |
| **RTFO** | 产品族 | "派工与产能提升"整体方案 |

> **两点值得注意**：① **内存数据库**是对"毫秒级决策"的直接工程应答，这个技术选择很对——Litho 派工的瓶颈经常在数据读取而非算法；② **SDR 的事件驱动架构**（感知→响应→决策流程→外部执行）比"定时轮询式派工"更适合 Litho 的高频状态变化（50% 变化发生在 5 分钟内）。

**其他相关**：AiDCS 智能缺陷分类（2019 年至今用于各厂 OQA，千万张用量，**准确率 99.6%**）、EAP（乐高积木式设计）、FDC、APC、RMS、DataLinks 数据平台、FAAS 芯片制造智能体平台。

**短板**：
- 成立仅 7 年，**量产沉淀年限是最大短板**——尤其 Litho 这种靠 Know-How 的区域。
- ARTD / AFPO / RTD / SDR 四个产品的职责边界在公开材料中**存在重叠**，选型时须明确各自的决策粒度与协同机制（谁定分配、谁定顺序、谁定搬送）。
- 无公开的 Litho 专项量化成效。

### 4.4 一个必须说清的判断：国产差距到底在哪

**不在算法。** 遗传算法、模拟退火、MILP 求解器、CP 引擎——这些国产与国际没有代差，论文里的东西开源求解器都能跑。

**在 Rule 库与量产 Know-How 的积累。** AMAT 的 RTD Rule 模板经过全球数十座 Fab、20+ 年迭代，覆盖几千种生产场景；Litho 区几百条 Rule，每条背后都是真金白银堆出来的经验。

**暴露时点是可预测的**：
- **新厂能用** —— 产品单一、异常少、约束简单
- **产能爬坡期开始吃力** —— 多产品混线、Dedication 冲突上升
- **成熟期暴露短板** —— 异常频发、Rule 覆盖度不足，系统能跑但 CT/WIP 就是比不过

**类比**：算法是发动机，Rule 库是导航地图。发动机再强，没有精准地图也开不到目的地。地图是钱和时间堆出来的，不是代码写出来的。

> **反向推论（对国产方案的机会判断）**：既然差距在规则沉淀，那么**L4 优化路线反而是国产的追赶捷径**——数学优化不依赖规则库，它依赖的是约束建模的准确性和参数质量。这两样可以在 1~2 年内通过扎实的现场工作建立，而 20 年的规则沉淀无法压缩。**这是国产 RTD 最该投的方向，而不是在规则库数量上追赶。**
