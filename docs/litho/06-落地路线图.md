# 落地路线图

### Phase 0：诊断（2~4 周，不写一行派工代码）

必须先量化白空间归因，否则后面全是盲调。

1. **白空间归因采样**：连续 2 周，对每台光刻机的每段空闲做归因（等罩 / 等料 / 换罩 / 温层升降 / 宕机 / 等检查 / 等人）。**这张图决定后面所有投入的优先级。**
2. **加工时间分布重建**：按「机台 × Reticle」配对统计，出均值与标准差。不要按机型统计——Nexperia 数据显示同机台不同罩的加工时间差异可达数倍。
3. **约束清单盘点**：Dedication 表（含分级）、Reticle 数量与 Pod 数、Tool Library 容量、Q-time 配置、嵌套 Timelink 清单、Reticle 寿命与检查限。
4. **现状基线**：按第五节指标体系取 4 周基线，**特别是人工干预率**。
5. **Rule 库体检**：数清有多少条、哪些从没触发过、哪些互相冲突。

### Phase 1：止血（1~3 个月）—— 投入产出比最高的阶段

不换系统，只改规则，优先做五件事：

1. **加入 Reticle 在位性权重**：当前机台已有的罩，其对应 Lot 直接加权。这一条通常立刻见效。
2. **加入温层差排序**（CN103390538B 的方法）：注意降温代价远高于升温，用环形差值而非绝对差。
3. **Reticle 剩余曝光次数硬校验**：`剩余 ≥ 本批所需`，不满足直接剔除候选并触发送检排程。缺这条等于裸奔。
4. **Q-time 剩余时间改非线性权重**：剩余 <20% 时权重陡升。
5. **Hot Lot 配额制**：按班限额，超配走审批。这是**管理手段解技术问题**，成本最低、效果最直接。

**预期**：白空间下降、换罩次数下降、Q-time 违规下降。此阶段的收益通常能覆盖后续投入。

### Phase 2：前瞻（3~6 个月）

1. **WIP 到达预测**：先做简单的（基于当前位置 + 剩余工时的确定性推演），不要一步跳到离散事件仿真。
2. **Reticle 预分配**：提前 10~15 分钟下发搬罩指令，与 Lot 搬送指令配对。
3. **ARHS 运力节流**：按搬运系统实际能力限制单次下发的移动请求数 N（IBM 专利的做法）。
4. **机台柔性度权重**：罩优先留给柔性最低的机台。
5. **Campaign 模式试点**：按 Layer Type 给机台分配 4 小时主攻层，设饥饿保护。

### Phase 3：优化（6~12 个月）

1. **选一个机群做 L4 试点**，不要全区上。
2. **权重全部改写为交换比**（`小时 / 次搬罩` 这种可解释形式）。
3. **数字孪生做规则/模型回归**：新逻辑先在仿真跑一周再上线。
4. **RTS-RTD 偏差阈值调优**：从 5 分钟附近开始试，监控 |L| 分布。
5. **建立闭环反馈**：RTD 偏差实时回灌 RTS，而不是单向流。

### Phase 4：自主（12 个月+）

1. 多目标自适应权重（按班次目标自动切换主指标）。
2. RL 策略学习 —— **前提是数字孪生验证环境已经可信**，否则是在真实产线上做实验。
3. 规则库瘦身：把被优化引擎覆盖的规则下线。
