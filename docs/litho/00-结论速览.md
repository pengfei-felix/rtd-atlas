# 核心结论速览

1. **Litho 不是"派工难"，是"三体问题"。** 其他区派工只解一个方程：`哪个 Lot 上哪台机`。Litho 要同时解三个耦合方程：`Lot → 机台`、`Reticle(+Pod) → 机台`、`机台 → 温层/Recipe 状态`。三者任一不到位，机台就空转。这是 Litho 派工与炉管、刻蚀、离子注入在**问题结构上的本质差异**，不是难度差异。

2. **80% 的 Litho 白空间（white space）不是产能不足，是"料到了罩没到"。** 行业公开结论一致指向这一点：Lot 到达机台但所需 Reticle 仍被别的机台锁定，或仍在 Stocker / 检查流程里。解法不在算法而在**预测窗口**——必须提前 10~15 分钟把 Reticle 搬送指令和 Lot 搬送指令一起发出去。

3. **规则库会必然膨胀到失控。** 头部量产线光刻区 RTD Rule 数量达到数百条并不罕见，优先级互相冲突，调一个指标牺牲另一个。纯规则（if-then）路线在产品单一的新厂够用，到**产能爬坡期 + 多产品混线 + 异常频发**阶段，必须引入规则分层、回放验证和局部优化。

4. **"调度 vs 派工"必须分层，且 RTD 要有推翻 RTS 的权力。** 公开仿真研究指向同一个结论：RTD 完全服从 RTS 计划时，现场异常会被放大；给 RTD 留出几分钟级的偏离容忍带，通常更稳。具体阈值不能照抄，必须用本厂历史回放标定。

5. **Litho 是 RTD 能力试金石。** 它同时考验 Lot 派工、Reticle / Pod 协同、机台专属性、Q-time 和序列相关 setup。能把 Litho 讲清楚，其他区才有展开基础；Litho 解不清，全厂 RTD 多半会退化成排序器。

6. **收益量级只能作参考。** 公开案例中常见几个百分点量级改善，但这些数字横跨不同年份、不同厂型、不同基线，**不能当承诺值**。正式项目要写的是本厂基线、验证窗口、主指标和约束指标。
