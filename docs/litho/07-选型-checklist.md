# 供应商选型 Checklist

**A. Reticle 协同能力（最能区分真假 RTD 的部分）**

- [ ] 是否把 Reticle 建模为**带位置 + 容量 + 搬运时延 + 寿命计数**的受限资源？（而非布尔量）
- [ ] 是否支持 **Pod 层约束**（Pod 上机后 Pod 内全部罩只能该机使用；同 Layer 才可同 Pod；Pod 数固定）？
- [ ] 是否支持 **Tool Library 容量**与**临界缓冲水平**（如 8/10 触发清库）？
- [ ] 是否支持 **Reticle 寿命双限**（Warning / Inhibit）与**预测检查限**？
- [ ] 排程输出是否包含 **Reticle 搬送指令**与 **Reticle 检查排程**？
- [ ] 是否按 **ARHS 运力节流**搬送指令下发量？
- [ ] 是否支持 **Dual Reticle** 场景？
- [ ] 是否实现**机台柔性度优先**逻辑（罩留给柔性低的机台）？

**B. 机台与整定建模**

- [ ] 加工时间是否支持**按「机台 × Reticle」配对**配置（而非按机型）？
- [ ] 是否支持**不相关并行机**（stepping speed / light intensity / flash 数）？
- [ ] 是否支持**嵌套的精度资格矩阵**（高精度机组可降级）？
- [ ] 整定时间是否支持**次序相关 + 机台相关**双维度？
- [ ] 是否支持**温层模型**（含升降温不对称）？

**C. 约束与合规**

- [ ] Dedication 是否支持**分级（1/2/3-level）**与按机群差异化配置？
- [ ] 是否支持**嵌套 Timelink 的可行性预检**（而非仅超时报警）？
- [ ] 重工是否支持**回原机台约束 + 独立优先级重算**？
- [ ] 宕机场景是否有**工程化决策表**（修复时长 / Q-time 剩余 / 备机等效性 / SPC 耗时）？

**D. 性能与架构**

- [ ] 在**贵厂真实产能量级**下的决策延迟 P99 是多少？（要求现场压测，不接受 Benchmark 报告）
- [ ] RTS 与 RTD 的**刷新频率**分别是多少？是否可配**偏差阈值**？
- [ ] RTD 是否有**推翻 RTS 的权力**和明确的触发条件？
- [ ] 偏差是否**回灌 RTS** 形成闭环？
- [ ] 规则是否支持**分层（Global / Local）+ 宏模块复用**？

**E. 可运维性（长期成本的决定项）**

- [ ] 新增/修改一条 Rule 的**冲突检测**机制？
- [ ] 是否提供**仿真/数字孪生环境**做规则回归？
- [ ] 优化引擎的决策是否**可解释**（能向产线说明"为什么这批先做"）？
- [ ] 权重是否以**可解释的交换比**形式暴露给工程师？

**F. 实绩（尽调重点）**

- [ ] 要求提供 **Litho 区的量化成效**（利用率 / 吞吐 / 搬罩次数 / 白空间），并说明**基线是什么**。
- [ ] 要求提供**可参访的同量级 12" 产线**案例。
- [ ] 要求说明**产能爬坡期与多产品混线期**的表现（这是国产方案的真实考场，新厂数据没有区分度）。
