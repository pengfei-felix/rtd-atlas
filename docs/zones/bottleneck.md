# 瓶颈判定

<div class="keyline" markdown>

**瓶颈不是"设计产能最低的那个区"，是"实际负荷最高的那个区"。** 这两件事在生产爬坡期和多产品混线时经常不是同一个区。

</div>

这页是区域分幅的横切面：先判出当前瓶颈在哪个区，再决定把优化资源往哪个区投。九个区各自的约束结构见 [区域总览](index.md)。

## 三层判定

判定瓶颈要过三道筛子，跳步就会判错。

| 层 | 算的是什么 | 数据来源 | 常见错误 |
|---|---|---|---|
| **① 理论产能** | 设备数 × 单片时间 × 可用率 | 设备清单、工艺参数 | 把它当瓶颈，忽略产品组合 |
| **② 实际负荷** | 需求量 ÷ 有效产能 | MES 在制、订单预测 | 有效产能不减 PM / 宕机 |
| **③ 动态瓶颈** | 按时段、按产品组合滚动计算 | 滚动窗口的实际排队 | 一年算一次，当成常量 |

**判据**：某区的负荷率持续高于其他区，且队列长度与周期时间同步上升 → 该区是当前瓶颈。

```
负荷率 = 需求工时 / (设备数 × 可用工时 × 有效产能折损)
```

有效产能折损必须扣掉：PM 时间、计划性停机、seasoning 期间的低效、非计划宕机。

## TOC 的四条推论

约束理论（TOC）的结论在派工上非常实用，且反直觉：

1. **瓶颈决定全厂产出。** 非瓶颈区提升效率，不会增加全厂产出，只会增加在制品。
2. **非瓶颈的"局部最优"是有害的。** 一个非瓶颈区如果满负荷运转，它产出的东西会全部堆到瓶颈前面。
3. **损失一小时瓶颈 = 损失一小时全厂产出；损失一小时非瓶颈 = 只是损失一小时。**
4. **投料速度要跟瓶颈走，不是跟订单走。**

这四条直接推出一条派工原则：**瓶颈区的派工优先级最高，非瓶颈区的任务是"准时喂饱瓶颈"，不是"自己跑满"。**

## 九个区什么时候成为瓶颈

| 区域 | 触发条件 | 机制 |
|---|---|---|
| **Litho** | 高层数产品占比上升、Reticle 数量不足 | 重入次数线性放大负荷，辅助资源卡住并行度 |
| **Etch** | 产品切换频繁、chamber 资质被锁 | 换 recipe 整定吃掉有效产能 |
| **Diffusion** | 小批量多品种、炉型不匹配 | 装载率上不去，炉次时间固定但产出低 |
| **Implant** | 多品种、能量/剂量分布分散 | 换线次数暴涨，setup 挤占加工时间 |
| **TF** | dedication 配得过死、靶材末期集中换靶 | 可用腔体数被人为收窄，或换靶停机成批出现 |
| **CMP** | 层数增加、pad 寿命管理粗放 | 去除率漂移导致返工，有效产能下降 |
| **Clean** | 换液集中、干燥能力不足 | 槽体停机是整段缺失，不是效率下降 |
| **Metrology** | 长 recipe 集中、异常期采样加密 | 按片数估产能会系统性高估，实际被几条长 recipe 吃穿 |
| **Sorter** | 载具数量不足、stocker 分区满载 | 机台空闲但上不了料，表现为假性 idle |

**后四个是隐性瓶颈的常客。** 它们通常不出现在产能报表的显著位置，因为：

- TF 和 Clean 的产能损失被记成"设备停机"，不记成瓶颈；
- Metrology 的产能被按片数平均，掩盖了 recipe 之间的巨大差异；
- Sorter 根本不生产，压根不进瓶颈计算。

判定隐性瓶颈有个简单办法：**看哪个区的队列在涨，但它的利用率报表却没有明显上升。** 这种情况通常是实际产能被某种非机台资源卡住了——靶材、药液、载具、长 recipe。

!!! warning "注意产品组合"
    瓶颈会随产品组合迁移。DRAM 与逻辑产品的瓶颈位置不同，同一条线在切换产品 mix 时，瓶颈可能在 Litho 和 Implant 之间来回跳。**动态瓶颈要按时段算，不能按季度算。**

## 五个常见误判

1. **拿设计产能当瓶颈。** 设计产能只说明"理论上谁最慢"，不说明"现在谁最堵"。
2. **有效产能不打折。** PM、宕机、seasoning 一律不算，负荷率会系统性低估。
3. **把最慢的单道工序当瓶颈。** 要看累计负荷，不是单点时长。炉管单道几小时，但设备少、批量大，未必是瓶颈。
4. **忽略批量的稀释效应。** 炉管一次装上百片，单片时间摊薄后可能比想象的宽松；刻蚀单片刻蚀反而更吃设备数。
5. **一年算一次。**

## 判定之后做什么

瓶颈确定后，派工策略要分两套：

| 对象 | 策略 | 关键指标 |
|---|---|---|
| 瓶颈区 | 优先供料、减少空转、保护产能不被打断 | 瓶颈利用率、饥饿时间 |
| 非瓶颈区 | 按瓶颈的消耗速度投料，控制队列长度 | 队列上限、投料节拍 |

非瓶颈区的目标函数里应该出现"**不要超过队列上限**"这一项。只写"最大化利用率"，系统一定会把 WIP 推到瓶颈门口。
