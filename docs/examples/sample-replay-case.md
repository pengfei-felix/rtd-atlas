# 历史回放案例

## 场景

某 Etch chamber 在 11:40 空闲，历史实际派工选择了一个普通 Lot，因为它已经在设备附近；新规则建议选择一个 Q-time yellow Lot，并提前预约下游 clean。

## 历史实际

| 时间 | 事件 |
|---|---|
| 10:20 | L001 clean track-out，进入 CLEAN → ETCH Q-time |
| 11:35 | ETCH_01_CHB 预计 5 分钟后空闲 |
| 11:40 | 历史派工选择 L031，原因：FOUP 已在 port 附近 |
| 12:05 | L001 才开始搬送 |
| 12:28 | L001 track-in，Q-time 剩余 12 分钟 |
| 13:20 | L001 etch out，下游 clean 排队 |

## 新规则推荐

| 决策点 | 推荐 |
|---|---|
| 11:35 | L001 进入 yellow，触发预搬送 |
| 11:40 | ETCH_01_CHB 选择 L001 |
| 11:42 | 锁定 downstream CLEAN_02 12:35–12:55 窗口 |
| 12:18 | L001 etch out |
| 12:37 | L001 进入 downstream clean |

## 对比结果

| 指标 | 历史实际 | 新规则回放 | 判断 |
|---|---:|---:|---|
| L001 当前窗口剩余 | 12 min | 48 min | 改善 |
| Etch setup loss | 0 min | +4 min | 可接受 |
| Downstream wait | 42 min | 19 min | 改善 |
| L031 等待增加 | 0 min | +31 min | 需计入普通批影响 |
| Q-time violation | 0 | 0 | 均未违规，但新规则风险更低 |

## 结论写法

这类回放不能只写“新规则更好”。专业写法应是：

> 新规则以 4 分钟 setup 损失和 L031 额外 31 分钟等待为代价，将 L001 的当前窗口余量从 12 分钟提升到 48 分钟，并将下游等待从 42 分钟降到 19 分钟。该策略适合 Q-time 黄区 Lot，但需要设置普通批等待上限，防止长期牺牲同一类 Lot。

## 需要继续验证

- 如果同一小时有多个 yellow Lot，是否会造成普通批饥饿；
- 下游 clean 预约被抢占时如何回滚；
- AMHS ETA 误差扩大时，预搬送是否仍有效；
- setup 损失在整班维度是否可接受。
