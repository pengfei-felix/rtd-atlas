# 求解器与算法选型

<div class="keyline" markdown>

**半导体调度不是“上最强求解器”就赢。** RTD 现场的第一原则是可执行、可解释、可回退。求解器适合局部、短周期、边界清楚的问题；实时派工仍需要规则兜底。

</div>

## 技术谱系

| 层级 | 方法 | 适用问题 | 风险 |
|---|---|---|---|
| L0 | FIFO / EDD / CR / SPT / WSPT | 单机、低复杂度、兜底排序 | 忽略资源同步和下游风险 |
| L1 | 加权 dispatch score | 多目标实时派工 | 权重不可解释会失控 |
| L2 | 规则库 + 可行性剪枝 | RTD 主流工程形态 | 规则膨胀、冲突治理困难 |
| L3 | Rolling horizon 局部优化 | 瓶颈区、短周期预约 | 边界条件处理不好会局部最优 |
| L4 | CP / MILP / CP-SAT | 组批、预约、setup 序列、小规模瓶颈 | 超时、不可行、建模维护成本高 |
| L5 | 仿真优化 / 元启发式 / 学习策略 | 策略标定、复杂多目标 | 解释性和上线稳定性弱 |

## 按问题选方法

| 问题类型 | 推荐 | 不推荐 |
|---|---|---|
| 实时派工排序 | 可行性过滤 + dispatch score + 规则兜底 | 大模型全局求解后再派工 |
| 炉管组批 | SRB / rolling window / 小规模 CP 或 MILP | 简单 FIFO 凑满炉 |
| Q-time 抢救 | 剪枝 + 下游预约 + 风险升权 | 只按剩余时间排序 |
| Etch chamber 选择 | chamber qualification + matching + setup score | tool 级平均能力 |
| Implant sequence | setup family campaign + 打断门槛 | 全局固定 campaign 不许打断 |
| CMP 派工 | pad/R2R 上下文 + 风险过滤 | 只按空闲 tool 派 |
| 瓶颈短周期预约 | rolling horizon + warm start | 一天排一次静态计划 |
| 全厂策略评估 | 离散事件仿真 + 多方案对比 | 直接在线 A/B 大范围试错 |

## 硬约束与软约束

| 类型 | 例子 | 处理 |
|---|---|---|
| 硬约束 | contamination、qualification、hold、Q-time 红线、设备 inhibit | 过滤，不参与权重折中 |
| 强软约束 | Q-time 黄区、Hot Lot、瓶颈饥饿 | 高惩罚，可被更高风险覆盖 |
| 软约束 | setup、搬送距离、负载均衡、recipe continuity | 目标函数加权 |
| 观测项 | 利用率、move 次数、规则命中次数 | 不直接驱动单次派工，做复盘 |

硬约束如果写成权重，迟早会被某个更高分的目标冲掉。RTD 里要先过滤，再排序。

## 求解器工程要点

### 1. Infeasible 处理

不可行不是异常，而是常态。每个优化模型都要定义：

- 哪些约束绝不放松；
- 哪些软约束可降级；
- 降级顺序是什么；
- 降级后 reason code 怎么写；
- 何时回退到规则。

### 2. 超时与 fallback

| 场景 | 处理 |
|---|---|
| 求解在时限内找到可行解 | 使用可行解，不必等最优 |
| 求解超时但有 incumbent | 使用当前最好解，记录 optimality gap |
| 求解无可行解 | 回退规则，输出 infeasible reason |
| 输入状态不完整 | 不调用求解器，直接降级规则 |

RTD 求解时限应以现场节拍定义。设备空闲等待 30 秒可能比求一个更优解更贵。

### 3. Warm start

Rolling horizon 必须利用上一轮解：

- 已经 track-in 的任务固定；
- 已搬送在途的资源尽量保持；
- 未过期预约优先保留；
- 只对受扰动窗口重算。

否则系统每次滚动都大幅改变计划，现场会认为排程不可信。

### 4. 目标函数可解释

不建议写成一串无意义权重。应写成交换比：

| 目标 | 示例解释 |
|---|---|
| Q-time 风险 | 进入红区的惩罚大于一次 setup 损失 |
| Hot Lot | Hot Lot 等待 1 分钟相当于普通批等待 N 分钟 |
| 搬送距离 | 多一次跨 bay move 需要被更高紧迫度证明 |
| setup | 一次 species 切换等价于 X 分钟产能损失 |

权重不是调参魔法，而是现场决策偏好的数学表达。

## 算法适配表

| 方法 | 优点 | 限制 | 半导体适配点 |
|---|---|---|---|
| Dispatch rule | 快、稳、可解释 | 全局预见弱 | RTD 兜底和高频实时派工 |
| SRB | 适合批加工组批 | 参数需标定 | Diffusion / furnace |
| GA / ACO / Memetic | 适合复杂组合优化 | 收敛和参数敏感 | 离线策略搜索、局部瓶颈 |
| CP | 约束表达强 | 大规模实时困难 | 预约、组批、序列约束 |
| MILP | 目标清晰、可审计 | 非线性和规模受限 | 小规模瓶颈、产能分配 |
| CP-SAT | 可处理逻辑约束和整数变量 | 仍需边界控制 | 短周期 rolling horizon |
| 离散事件仿真 | 能评估策略影响 | 不直接给最优解 | 回放、策略验证、WIP cap 标定 |
| 强化学习 | 可学习复杂策略 | 安全性、解释性、样本效率问题 | 仅建议离线研究或建议层，不做硬执行 |

## 典型反模式

| 反模式 | 后果 |
|---|---|
| 全厂一次性 MILP 最优 | 模型庞大、状态过时、上线不可执行 |
| 用 AI 替代规则库 | 缺少硬约束和 reason code，现场无法信任 |
| 只看 optimality gap | 现场更关心是否按时、可解释、可回退 |
| 权重不断手工调 | 指标漂移，规则不可复现 |
| 求解器无兜底 | 超时或不可行时设备空等 |

## 推荐架构

```text
硬约束过滤
  → 候选集缩小
  → 规则 / score 快速排序
  → 局部求解器优化关键窗口
  → fallback rule
  → reason code + 回放验证
```

求解器不是 RTD 的替代品，而是 RTD 在边界清楚场景下的增强模块。
