# Shadow Mode 影子模式

<div class="keyline" markdown>

**影子模式是 RTD 上线前的体检。** 系统在线生成推荐，但不下发执行；用推荐和人工实际派工的差异，暴露数据、规则和接口问题。

</div>

## 影子模式看什么

| 维度 | 问题 |
|---|---|
| 可执行性 | 推荐是否被现场硬约束否决 |
| 数据延迟 | 推荐时状态是否已过期 |
| 解释性 | 为什么推荐这个 Lot 是否说得清 |
| 差异归因 | 与人工派工不同的原因是什么 |
| 稳定性 | 推荐是否频繁抖动 |

## 差异分类

| 差异 | 判断 |
|---|---|
| 系统更优 | 人工忽略 Q-time / setup / ETA |
| 人工更优 | 系统缺少隐性约束 |
| 数据问题 | 系统状态滞后或错误 |
| 目标差异 | 人工在执行未建模目标 |
| 不可判断 | 缺少结果或现场解释 |

## 上线门槛

| 门槛 | 说明 |
|---|---|
| 硬约束失败率低 | 推荐不能频繁不可执行 |
| 差异可解释 | 大部分差异有 reason code |
| 数据延迟可控 | 关键状态延迟在阈值内 |
| 指标不恶化 | Q-time、质量、普通批 CT 不被牺牲 |
| fallback 可用 | 异常时能退回规则 |
