# RTS 与 RTD 分层

## 核心原则

调度（RTS，分钟级到小时级的计划）和派工（RTD，秒级到分钟级的实时决策）必须分层，且 **RTD 要有推翻 RTS 的权力**。

RTD 完全服从 RTS 时，现场一旦发生宕机、插单、料未到，计划就失真，而系统还在执行旧计划——这是国内很多厂的实际状态：RTD 沦为 RTS 的「传声筒」。

## 阈值的意义

公开仿真研究给出的量级是：**RTD 完全服从 RTS 时吞吐量下降超过 50%；偏离阈值设在 5 分钟左右时吞吐最优。** 这个数字依赖厂型与基线，不能照抄，但结论方向明确——**必须给 RTD 留一个「计划偏离容忍带」**。

阈值过小：RTD 频繁推翻计划，RTS 失去意义，系统震荡。
阈值过大：RTD 变成执行器，失去应对异常的能力。

## 设计要点

1. **偏离判据要可解释**。不能只是概率阈值，要说清「什么情况下 RTD 有权改计划」——设备宕机、料未到、Q-time 将超。
2. **推翻要留痕**。每次 RTD 覆盖 RTS 计划都记录原因，用于事后评估阈值是否合理。
3. **RTS 要能看到执行偏差**。滚动重排时把已发生的偏离吃进去，否则计划与现场会越走越远。
