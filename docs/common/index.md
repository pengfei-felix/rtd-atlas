# 通用规则

九个区都要用的那一层基础规则：优先级继承、老化升权、时间窗预算、辅助资源预留、冻结与改派门槛。九个区的排序逻辑本来就一样，差的是参数——所以提炼成一份放在上层，各区**加载**它，再追加自己的工艺特化。

**区域层只能改参数，不能改逻辑。** 阈值、权重、时间常数各区按工艺调；要改判断逻辑，就是这一层升版本，对九个区一起生效。

下面按功能域列全部 57 项，点域名跳到对应清单。每条的「类型」口径与区首页一致：**校验**改可派性、**约束**改候选集、**策略**只改顺序、**接口**只给信息。

## 功能域

| 功能域 | 条数 | 管什么 |
|---|---|---|
| [优先级与排序](#priority) | 17 | 谁先做：优先级继承、老化、出货紧急度、阶段目标 |
| [人工干预与任务管理](#manual) | 13 | 人怎么改系统：指定/禁止机台、插单、替换、监控 |
| [数据与系统接口](#interface) | 10 | 系统之间怎么对齐：去向选择、MES 回传、Flow 与 CT/PT 数据 |
| [资源与设备](#resource) | 9 | 辅助资源与设备状态：腔体、PM、控片、载具合并 |
| [时间窗与投料](#qtime) | 4 | 什么时候必须做：Q-time 卡控、下游安全站、线路平衡 |
| [可行性与约束检查](#constraint) | 4 | 能不能派：机台状态、LoadPort、recipe、MES constraint |

## 优先级与排序 {#priority}

决定"先做谁"。这一域的 17 条几乎全是策略：不改可行性，只改顺序。它们叠在一起才形成最终的排序序列，缺一条不会报错，但队列会慢慢走样。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| Qtime Urgency | 策略 | 对已进入 Q-time 的正常 flow lot 计算紧急程度，按紧急程度派工 | 走廊内的批与正常批同权排队，急单被压住 |
| Remaining Qtime | 策略 | 算 Lot 剩余 Q-time，低于阈值就 speedup；并逐站算「剩余 Q-time / 剩余 CT」，低于阈值自动提速 | 只看当前站，前面几站吃掉余量，到站已经来不及 |
| Critical Ratio | 策略 | 依历史或用户给的 PT/CT 算出货紧急程度（critical ratio），据此派工 | 只按进站先后排，交期近的批被平均掉 |
| Schedule Monitor | 策略 | 派工时优先考虑快要到期的 schedule monitor | 监控批过期，数据断档 |
| 高等级 | 策略 | 用户提供高等级 Lot（Bullet / Hot）识别方式，优先派 | 高等级批混在正常队列里，识别出来时已经晚了 |
| Bullet Lot | 策略 | 用户提供 bullet lot 识别方式，优先派 | 客户承诺批次被普通批挤在后面 |
| Rework | 策略 | 优先派 rework lot | 返工批压着，返工损失继续滚 |
| RunCard | 策略 | 优先派 run card lot | 工程批排不上，实验窗口错过 |
| 等级 | 策略 | 依 Lot 的 MES priority 派货 | 系统优先级与现场优先级不一致，现场靠人催 |
| Rule Sorting 自定义 | 策略 | 每个 Lot 带齐全部排序标记，最终按用户设定的 Sorting 排；各规则权重可调 | 排序写死在代码里，产品组合一变就要改程序 |
| FIFO | 策略 | 依先进先出规则派货 | 同级之间没有依据，插单全凭现场 |
| Future Merge | 策略 | 检查 inline 分批 Lot，若合批站已有部分 Lot 到站，未到站的优先 | 分批落后的那几批拖着，合批站干等 |
| Pilot | 策略 | 针对 Litho、Etch、CMP 等需要 Pilot 的站优先派工 | 首片没人跑，机台放着等放行 |
| Stage Move | 策略 | 按用户设定的 daily stage target 查当天派货记录，优先补未达标的 Lot | 阶段目标到晚上才发现差一截 |
| Stage Move Ratio | 策略 | 按 product 的 stage target 完成 ratio 排序，ratio 低的优先；可从上游提前拉同 product 加权重 | 各产品齐头并进，月底集中赶货 |
| Bullet Lot 预约 | 策略 | 预测高等级 Lot 到站时间与当站 run 货时间，提前预约未来 Step 的机台或 Chamber | 高等级批到了没机台，或者机台空等它 |
| 按 LoadPort / 整机预约 | 策略 | 支持高等级 lot 按 load port 或整机预约，其他 lot 看到被预约会等待 | 预约占不住，位置被别的批插走 |

## 人工干预与任务管理 {#manual}

人怎么绕过系统。九条 MFG Control 是"配置口"，四条任务管理是"运行时口子"。**这类功能的价值在于兜底，不在于效率**——没有它，异常只能等系统改版；有它，又要防被滥用。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| 设定站点机台高优先 | 策略 | 用户设定某 product 某站点的某机台优先，Lot 在这些机台优先派 | 关键层想固定用某台机，只能靠人喊 |
| 设定站点机台低优先 | 策略 | 用户设定某 product 某站点某机台优先级最低 | 有问题的机台排不掉，只能等它自己坏 |
| 设定站点指定机台 | 约束 | 用户设定某 product 某站点只有某些机台可派，RTD 只往这些机台派 | 工程要求跑不了，只能人工插件 |
| 设定站点禁止机台 | 约束 | 用户设定某 product 某站点某些机台不能派，RTD 会 Block 对应 Lot | 问题机台继续吃料，异常批量放大 |
| 设定 Recipe 指定机台 | 约束 | 支持分组设置：一部分机台群组优先跑某几种 recipe，另一部分跑另几种 | recipe 在群组间乱串，整定时间翻倍 |
| 设定机台 Lot Size | 约束 | 可设机台最小派工片数，小于限制则 block 派工 | 小片连续上机，机台效率被切碎 |
| Mark Lot | 校验 | 支持 mark lot，被 mark 的 lot 不派工 | 问题批被继续派出去，扩大返工面 |
| Reserve Queue | 策略 | 支持手动把 lot 加入 Reserve Queue，加入的 Lot 派工时优先考虑 | 急单只能靠口头插队，没人记得 |
| 指定优先 / Block 机台 | 策略 | 正常流站的机台群组中可指定某几台优先；也可指定某 product 某站点某机台不能派 | 与前几条口径重叠，容易出现两套配置互相对冲 |
| 派工监控 | 接口 | 提供界面查询已派工记录及进度 | 派了没派成无处可查，只能去翻日志 |
| 插单 | 接口 | 支持手动把需要的工单指派到机台任务 | 急件进不来，只能等下一轮派工 |
| 替换 | 接口 | 支持手动替换已派工工单 | 排错了只能等它做完 |
| 删单 | 接口 | 支持手动删除已派工工单 | 死单挂着占位，机台窗口被吃掉 |

## 数据与系统接口 {#interface}

系统之间怎么对齐。这一域有两类：一类是**去向**（Lot 出了这台机往哪走），一类是**数据**（派工引擎读什么、回传什么）。它们不改排序逻辑，但少一条，前面所有规则都算不出来。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| Where Next（全自动） | 接口 | 全自动模式下 lot 搬出设备时找下一台设备；可用就直接送，否则考虑减少搬送，送到缓冲区或 Stocker | 料挂在机台上等下一站，占着 load port |
| 半自动选下工序 Stocker | 接口 | 半自动模式下离开当前工序时，找到下一道工序设备相近的 Stocker | 送到远端仓库，下次搬运多绕一圈 |
| Sampling | 接口 | 支持 Scan 或 Sampling，用户自定义规则判断 lot 是否进 YE 站点 | 抽样规则写死，改一次要改程序 |
| Transfer Time | 策略 | 依传送距离或时间汇总，优先选传送距离短或时间短的 lot | 最近的料不取，搬运时间白付 |
| Auto 模式 | 接口 | 支持自动与半自动模式切换 | 只能全自动，出异常时无法降级 |
| 提前派工 | 接口 | 优化派工时机，例如 ProcessEnd 之前先开始派货 | 出机才开始找下一站，白等一段 |
| MES 交互 | 接口 | 回传 MES：能派的 Lot 显示对应 Sorting，不能派的显示 Reason | 现场不知道为什么没派，只能问工程师 |
| 功能开关 | 接口 | 所有用户设定的功能都有开关控制是否生效 | 一条规则出问题只能整体回滚版本 |
| Flow 数据 | 接口 | 提供完整且定时更新的 Product Flow，含 Normal 与 Adhoc（SRC、RRC、Sorter、Rework） | 特殊路径不在系统里，派工直接走错工序 |
| CT/PT 数据 | 接口 | 计算 Lot 的 CT 与 PT（Product、Recipe、Step 维度），并提供手动维护接口 | 时间参数过期，所有排程估算一起偏 |

## 资源与设备 {#resource}

辅助资源、设备状态和控片。这一域的共同点：**它们都不是"机台可用/不可用"这么简单**——腔体会退化、PM 有窗口、控片有水位、载具可以合并。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| Chamber IDLE Time | 策略 | 选 ppid 时看机台当前 chamber idle 时间，优先选先 idle 的 chamber | 总用同一批腔，其余腔空转，寿命也白耗 |
| PM Window | 策略 | 依机台 PM 时间、PT、CT 派货时避开 PM 窗口 | 派到即将 PM 的机台，做到一半停机 |
| Qtime PM Window | 策略 | 依 PMS 计划开始时间反算 Q-time 最晚触发时间 | 走廊中途撞上 PM，整段超时 |
| NPW 低库存自动提升 | 策略 | NPW 可用量低于安全存量时自动提升派工等级 | 控片见底不报警，靠人盯 |
| NPW 安全水位 | 策略 | 某些清洗机发现 NPW 可用片数偏少时优先去清洗 | 控片断料，产线临时停等 |
| NPW 低水位前制程优先 | 策略 | 控片安全库存不足时提前准备 | 等到断料才反应，停线已成事实 |
| NPW Recycle 暂 Block 小片 | 策略 | 让 NPW recycle flow 的某些清洗机暂 block 小片数 lot，等待 merge | 小片把槽位切碎，回收效率低 |
| 同 FOUP 多 Lot | 接口 | 一个 FOUP 内有多个 Lot 且机台允许时（相同 recipe 或允许多 recipe 同 port），可同时派该 FOUP 内所有 lot | 一个框里的料分批上机，多搬一趟 |
| Season + Product | 接口 | 某些 lottype（如 season lot）不可单独派工，需要时找 season lot 与 production 一起派 | season 片单独跑，白占一段产能 |

## 时间窗与投料 {#qtime}

什么时候必须做，以及往产线放多少。这一域只有 4 条，但它是**全厂唯一按事件计时**的一层——走廊的起点在清洗出槽，终点在下一站上机，中间任何一段都不能独立管。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| Qtime WIP Control | 校验 | 依 flow 设定的 Q-time 区间，结合区间内既有 Lot 与机台状况算各站可放 Limit，在 Q-time 起始站管控派货 | 走廊里塞太多批，进一个超一个 |
| Qtime Manual Control | 策略 | 用户提供各段触发 speedup 的剩余 Q-time 与起始站 WIP Limit，系统据此判断是否 speedup 或 control，优先级高于 Auto | 特殊产品没有手动口子，只能改全局参数 |
| Qtime Loop Control | 校验 | 派工时看下游机台，若下游全部不可用（down 或 constraint），把 Lot 停在安全站等待 | 明知下游不通还往下送，等成 over due |
| Line Balance | 策略 | 依 PT/CT 与瓶颈群组、缺货堆货设定，让瓶颈群组从上游拉货；WIP 少时优先拉，已堆货则停拉 | 非瓶颈区自管自跑，WIP 全堆到瓶颈门口 |

## 可行性与约束检查 {#constraint}

最后一道闸：能不能派。四条里有三条是**设备侧**检查，一条是**工艺侧**检查（MES constraint）。它们是派工引擎输出的最后一步，也是最容易被省略的一步——省了不会立刻出错，但现场会逐个退回。

| 功能 | 类型 | 功能描述 | 不管会怎样 |
|---|---|---|---|
| EQP Status Check | 校验 | 派工条件触发后检查机台其他状态与设置，确认处于可派工状态 | 派到 PM、暖机或故障的机台，EAP 退回，白排一轮 |
| 机台 / LoadPort 可用检测 | 校验 | 派下一批时自动检测机台或 LoadPort 是否可用，把 Lot 派到空闲 LoadPort | 派到已占用的 port，料根本搬不过去 |
| EQP Constraint & Recipe Check | 校验 | 派工时检查 lot 属性与机台限制：机台状态、MES normal constraint、recipe 状态、ppid 状态 | 四个状态任一不对，计划现场不可行 |
| MES Constraint 过滤 | 约束 | 跟随 MES 规则，把有 MES constraint 的 Lot 过滤或标记并附 reason；算未来站要考虑路宽并过 CSN 校验 | 绕过 MES 硬约束，排出来的计划违反工艺规则 |
