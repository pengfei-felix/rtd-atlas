# G3 · 资源与污染

<div class="keyline" markdown>

**「计划可行、现场做不到」八成出在两层：辅助资源没抢到，污染等级没对上。** 辅助资源的状态和寿命归通用层统一管，搬运与使用由区域层决定——单个区都管不全。

</div>

!!! note "和跨幅专题的分工"
    资源有哪几种、各自的共享模式、寿命和锁定机制，见 [辅助资源流转](../topics/support-resource.md)。

    这页讲通用层的部分：跨区资源池怎么划、污染等级怎么定义成矩阵、载具怎么分配、冲突怎么裁。

## 核心结论

1. **资源池是 fab 级的，不是区级的。** Reticle 归 Litho 管，但可能被跨区调配。
2. **污染隔离是 P0，不是权重。** 它不参与排序，只参与过滤。
3. **污染等级要定义成矩阵，不是单一标签。** 单向污染和双向污染的处理完全不同。
4. **载具是最容易被忽略的独占资源。** FOUP 数量不够，机台再空也跑不起来。
5. **消耗型资源要有预警线。** 缺料不是仓储问题，会直接变成设备 idle。

## 四类共享模式

统一成四种，每种的派工动作不一样：

| 模式 | 典型资源 | 派工动作 |
|---|---|---|
| **独占** | Reticle、Pod、载具 | 抢占 + 锁定 + 释放，同一时刻只能一处用 |
| **成组** | Boat、石英舟 | 按批次容量成组占用，组不满也占 |
| **退化** | Pad、靶材、conditioner | 按状态段限制可用范围，不按可用/不可用 |
| **消耗** | 气体、slurry、化学品 | 按水位预警，低于阈值触发限制 |

**退化型最容易配错。** 只设一个寿命上限，风险会集中在寿命末期那几批。正确做法是分段，见 [CMP 的 pad 分段派工](../cmp/index.md)。

## 跨区资源池

| 资源 | 名义归属 | 实际归属 | 冲突点 |
|---|---|---|---|
| Reticle / Pod | Litho | fab 级池 | 工程批与量产批争抢 |
| Boat / 石英件 | Diffusion | 区级池 | 不同炉型不能混用 |
| Pad / Conditioner | CMP | 机台级 | 分区 pad 不能跨机 |
| 载具（FOUP / Cassette） | 无明确归属 | fab 级池 | 最典型的无人管资源 |
| 靶材 / 气体 | TF / Implant | 区级 + 供应 | 供应商交期影响可用性 |

归属和使用范围不一致的地方，就是计划失效的高发点。「名义归属 + 实际使用范围 + 锁定规则」这三样必须都显式写出来。

### 预留优先级

资源争抢时按这个顺序：

```text
1. P1 走廊（Q-time 红区）申请的资源
2. Hot Lot 所需资源
3. 瓶颈区常规生产
4. 非瓶颈区常规生产
5. 填炉 / 工程 / 验证批
```

第 1 条容易被漏。走廊已经红了，却因为 Reticle 被一个填炉批占着而超时——这类事故在 Fab 里一点都不罕见。

## 污染等级矩阵

单一标签（"Cu 机台"/"Non-Cu 机台"）不够用，要定义成矩阵：

| | 目标：Cu | 目标：Non-Cu | 目标：金属（Al/Ti） |
|---|---|---|---|
| **来源：Cu** | 允许 | **禁止** | **禁止** |
| **来源：Non-Cu** | **禁止** | 允许 | 视工艺而定 |
| **来源：金属** | **禁止** | 视工艺而定 | 允许 |

三档判定：

| 判定 | 含义 | 派工动作 |
|---|---|---|
| **允许** | 无交叉污染风险 | 正常派工 |
| **禁止** | 不可逆污染 | P0 过滤，不允许 override |
| **视工艺而定** | 需要工艺 owner 判定 | 查规则表，缺失则默认禁止 |

「视工艺而定」这一格必须有明确来源。默认放行的结果，是没人知道某台机什么时候被污染的。

### 污染状态的两个来源

| 来源 | 可靠性 | 问题 |
|---|---|---|
| 机台配置（静态） | 高 | 改配置后不同步就过期 |
| 历史加工记录（动态） | 中 | 追溯期设太短会漏，设太长会过度隔离 |

建议：静态配置为主，动态记录做校验。两者不一致时按**更严格**的一边处理，并告警——不一致本身就说明有问题。

## 载具池分配

载具是 Fab 里最容易变成"谁都在用、没人负责"的资源。

| 字段 | 说明 |
|---|---|
| `carrier_id` | 唯一标识 |
| `carrier_type` | FOUP / Cassette，尺寸、slot 数 |
| `contamination_class` | 与污染矩阵同一套口径 |
| `current_location` | 机台 / stocker / 搬送中 |
| `reserved_for` | 预留给哪个 Lot 或走廊 |
| `clean_due` | 下次清洗时刻 |

三条规则：

1. **载具随 Lot 走，不随区走。** 载具被卡在某个区，等于把 WIP 卡在那里。
2. **污染等级跟随载具，不跟随 Lot。** Lot 换载具必须重新判定。
3. **预留优先于即时分配。** 走廊预留的载具不能被常规派工抢走。

## 典型派工问题

### 问题 1：Reticle 被锁在别的机台

| 项 | 内容 |
|---|---|
| 现象 | Lot 到了机台空转，等光罩 |
| 根因 | Reticle 只有区级视图，没有全局占用 |
| 解法 | Reticle 进 fab 级池，带锁定和释放事件 |
| 指标 | reticle wait time、lock conflict count |

### 问题 2：污染等级只在配置里，实际已漂移

| 项 | 内容 |
|---|---|
| 现象 | 静态配置显示干净，实际已加工过污染批 |
| 根因 | 只依赖机台配置，没有历史校验 |
| 解法 | 静态 + 动态双源，冲突时按严格侧处理 |
| 指标 | config-vs-history mismatch count |

### 问题 3：载具不足造成的假性 idle

| 项 | 内容 |
|---|---|
| 现象 | 机台显示空闲，但没有 FOUP 可以上料 |
| 根因 | 载具不在 RTD 的资源视图里 |
| 解法 | 载具池建模，带位置和预留 |
| 指标 | carrier wait、false idle rate |

### 问题 4：消耗型资源缺料没预警

| 项 | 内容 |
|---|---|
| 现象 | 计划排好了，跑到一半发现靶材/气体不够 |
| 根因 | 只看当前水位，没有按计划消耗量预测 |
| 解法 | 水位 + 计划消耗做滚动预测，低于阈值触发限制 |
| 指标 | material-shortage idle、consumable warning hit rate |

## 落地节奏

G3 依赖资源台账，接不齐就没法做。按这个顺序推进：

1. **先接状态**：把 Reticle、Pod、Boat、Pad、载具的位置和状态接进 RTD 视图。
2. **再做硬约束**：污染矩阵、qualification 这类纯过滤规则先上，收益最直接。
3. **然后做预留**：从 Reticle 和走廊相关的资源开始。
4. **最后做消耗预测**：靶材、气体、slurry 的滚动预测。

前两步做完，现场"计划可行、做不到"的问题能消掉大半。后两步是锦上添花。
