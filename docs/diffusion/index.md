# Diffusion 区派工档案

<div class="keyline" markdown>

**Diffusion 的核心不是“派哪台炉”，而是“这一炉该不该现在开”。** 炉管工时长、批量大、升降温慢，错误派工不会立刻暴露，但会在几个小时后变成装载率低、Q-time 爆窗和瓶颈漂移。

</div>

## 核心结论

1. **这是强 batch 问题。** 决策对象不是单个 Lot，而是一组 Lot + 一台炉 + 一套温度曲线。
2. **组炉和派工不能拆开。** 先组炉再派工，会把“凑满”和“赶窗口”割裂。
3. **满炉不是唯一目标。** 为了装载率硬等，可能把 Q-time 等爆；为了救 Q-time 半炉开，又会牺牲产能。
4. **升降温比 recipe 名字更重要。** 很多损失来自温区切换，不是来自加工本身。
5. **Boat / Quartzware 是隐藏产能。** 炉管空不代表能开炉，舟具、石英件、清洁状态都会卡住。

<div class="rtd-strip" markdown>

<span>决策粒度</span> Lot set → Tube / Furnace → Temperature profile → Boat  
<span>核心矛盾</span> 装载率 vs Q-time vs 温区切换

</div>

## 与 Litho 的结构差异

| 维度 | Litho | Diffusion |
|---|---|---|
| 决策对象 | 单个 Lot 上哪台曝光机 | 哪些 Lot 拼成一炉 |
| 主要资源 | Reticle / Pod / Tool Library | Tube / Boat / Quartzware / 温区 |
| 时间尺度 | 分钟级派工，短 setup | 小时级加工，长驻留 |
| 主要风险 | 机台等罩、Q-time、dedication | 半炉开、等炉、升降温损失、Q-time 前后窗 |
| 优化重点 | 资源同步到位 | 组批质量 + 炉管节拍 |

Diffusion 看起来动作少，但每次动作都重。Litho 派错一个 Lot，几分钟后还有机会修；Diffusion 开错一炉，几个小时内都改不了。

## 八类约束结构

### 1. 批量装载约束

炉管设备的加工时间基本不随 Lot 数线性增加，所以装载率直接影响有效产能。

| 要素 | 派工含义 |
|---|---|
| 最大装载量 | 决定一炉能吃多少 Lot / wafer |
| 最小经济装载 | 低于这个数开炉，产能损失明显 |
| Lot 尺寸差异 | 25 片满 Lot 和 split lot 不能只按批数看 |
| Carrier / Boat 容量 | 真正限制可能在舟具，不在炉管 |

高频错误：只按 Lot 数凑批，不按 wafer 数、工艺族和 boat 容量一起算。

### 2. Recipe 与温度曲线

同 recipe 不一定能同炉；同温度曲线也不一定能同炉。要看 recipe family、气氛、时间、温区、产品限制。

| 层级 | 说明 |
|---|---|
| Recipe | MES 路线上的工艺菜单 |
| Recipe family | 可同炉或可连续跑的一组 recipe |
| Temperature profile | 升温、恒温、降温曲线，决定 setup 损失 |
| Ambient / Gas | O2、N2、H2 等气氛要求，影响切换和安全 |

工程上更应该按 **campaign family** 管，而不是只按 recipe code 管。

### 3. 长加工与非抢占

开炉后不能临时把 Lot 拿出来，也不能中途插入 Hot Lot。RTD 决策必须在开炉前把风险算完。

重点校验：

- 开炉后是否会卡住下游 Q-time；
- 同族 Lot 是否马上要到，值得等多久；
- Hot Lot 是否应该单独开炉；
- 炉管加工期间 PM 是否会撞上后续计划。

### 4. 前窗 Q-time

清洗后到进炉通常有严格窗口。为了等满炉而让清洗后 Lot 长时间排队，是 Diffusion 最常见的调度坑。

正确做法是区分两类等待：

| 等待位置 | 风险 |
|---|---|
| 清洗前等待 | 通常更安全，可控 |
| 清洗后等待 | 已进入窗口，必须严控 |

一句话：**可以在窗口外等满炉，不要在窗口内硬凑批。**

### 5. 后窗 Q-time

出炉后到下一工序也可能有窗口。长炉程结束时如果下游没有准备好，前面几个小时的排程就白做。

RTD 开炉前至少要看：

- 预计出炉时下游设备是否可用；
- 是否会形成同一时间大批 Lot 出炉冲击；
- AMHS 是否有搬送余量；
- 下游是否也有 batch 设备，是否需要二次组批。

### 6. Boat / Quartzware 寿命

舟具和石英件不是“在 / 不在”这么简单。它们有材质、清洁状态、使用次数、污染限制和更换周期。

| 状态 | 派工处理 |
|---|---|
| Green | 正常可用 |
| Yellow | 限制关键产品或高风险 recipe |
| Red | 禁止新开炉，触发清洁/更换 |

如果这些状态不进 RTD，系统会把理论可用炉管当成实际可用产能，排出来的计划自然偏乐观。

### 7. 机台专属性与工艺稳定性

关键层或关键产品可能绑定固定炉管，以控制膜厚、均匀性和污染风险。专属性不能简单视为低效，它本质上是良率约束。

问题在于：专属性长期不复核，会把负载压死在几台炉上。应建立例外流程：

- 绑定原因；
- 可替代炉管；
- 切换前需要的验证；
- 宕机时的临时解绑审批。

### 8. 炉管清洁与 PM 节拍

Diffusion 的 PM / clean 往往不是短暂停机，而是改变一段时间内的可用产能。派工需要知道：

- clean 前还能不能再跑一炉；
- clean 后是否需要 seasoning；
- 哪些 recipe 会加速污染；
- PM 是否应该安排在 campaign 切换点。

## 组炉策略

### SRB 思路：先判断该不该等

组炉不是“够了就开”，也不是“一定等满”。比较稳的现场逻辑是：

```text
当炉管即将可用：
  1. 检查队列中是否有 Q-time / Hot Lot
  2. 检查同 family Lot 在未来 Δt 内是否将到达
  3. 若等待能显著提高装载率，且不触发窗口风险 → 等
  4. 若等待会让已清洗 Lot 进黄/红区 → 立即开炉
  5. 若下游不可接收 → 暂缓启动或调整组合
```

这里的 Δt 不能拍脑袋，应按历史到达节奏、炉管加工时长、最小经济装载来标定。

### 三种开炉模式

| 模式 | 适用场景 | 风险 |
|---|---|---|
| 满载模式 | 稳定产品、到达集中、Q-time 宽 | 等待时间过长 |
| 时间窗模式 | Q-time 压力高、到达分散 | 装载率下降 |
| Campaign 模式 | 同 family 连续到达、setup 代价大 | Hot Lot 被饿死 |

成熟产线通常三种模式并存，而不是全区一条规则。

## 典型派工问题

### 问题 1：为了满炉，把 Q-time 等爆

| 项 | 内容 |
|---|---|
| 现象 | 炉管装载率好看，但清洗后 Lot 频繁超窗 |
| 根因 | 只考核装载率，没有区分窗口内外等待 |
| 解法 | 设置清洗后最大等待；在清洗前做组炉预测 |
| 指标 | 清洗后等待时长、Q-time violation、半炉开比例 |

### 问题 2：半炉开太多，瓶颈产能被吃掉

| 项 | 内容 |
|---|---|
| 现象 | Q-time 降了，但炉管有效产能下降 |
| 根因 | 红区救火过多，没有入口限流 |
| 解法 | 限制进入紧窗口的 Lot 数；黄色阶段提前锁炉 |
| 指标 | 平均装载率、红区开炉次数、瓶颈利用率 |

### 问题 3：温区切换损失被低估

| 项 | 内容 |
|---|---|
| 现象 | 炉管利用率高，产出却上不去 |
| 根因 | 派工只看 recipe，不看温度曲线顺序 |
| 解法 | 建 campaign family，减少大幅升降温切换 |
| 指标 | 温区切换次数、setup loss、同 family 连跑炉数 |

### 问题 4：Boat / 石英件成了隐性瓶颈

| 项 | 内容 |
|---|---|
| 现象 | 炉管空闲，但合适舟具不可用 |
| 根因 | 辅助资源没进派工模型 |
| 解法 | 组炉时同步锁定 Boat；寿命和清洁状态进 RTD |
| 指标 | 因舟具等待的 idle time、boat conflict count |

## 深度案例库

| 案例 | 现场症状 | 根因判断 | RTD / APS 策略 | 验证指标 |
|---|---|---|---|---|
| 满炉等待爆窗 | 装载率高，清洗后 Lot 频繁擦 Q-time | 把装载率当主指标，窗口内等待未限流 | 清洗前组炉预测，清洗后设置最大等待；yellow 阶段提前锁炉 | post-clean wait、Q-time violation、load factor |
| 半炉救火过多 | Q-time 降了，但瓶颈炉管产能掉 | 入口投料失控，红区才救 | Q-time 走廊入口 cap；yellow 阶段分配炉管预约 | half-batch ratio、furnace TH、red-start count |
| 温区切换损失隐形 | 炉管忙但产出不高 | recipe code 相同/不同不能代表温区切换代价 | 建 temperature profile family，campaign 在温区层面优化 | temperature switch count、setup loss |
| Boat 成为隐藏瓶颈 | 炉管空闲，合适 Boat 不在或寿命不足 | 辅助资源没参与组炉 | 组炉时同步锁定 Boat / Quartzware，寿命分 Green/Yellow/Red | boat wait、resource conflict count |
| 出炉波峰打穿下游 | 一批炉同时出，后段 clean / metrology 堵塞 | 开炉只看入口，不看出炉接续 | 开炉前预测出炉波峰，必要时错峰或预约下游 | downstream wait、outflow burst、reservation hit |

## 指标体系

| 层级 | 指标 | 用途 |
|---|---|---|
| 主指标 | 有效出片、瓶颈炉管利用率 | 看产能 |
| 约束指标 | Q-time 违规率、清洗后等待、Scrap / Reclean | 防止靠风险换产能 |
| 观测指标 | 平均装载率、半炉开比例、温区切换次数、Boat 等待 | 定位损失 |

注意：**装载率只能做观测指标，不能单独做主指标。** 单看装载率，会诱导系统硬等满炉。

## 落地路线

1. **先把组炉规则表化**：哪些 recipe/family 可同炉，哪些不能。
2. **接入窗口状态**：区分清洗前等待和清洗后等待。
3. **接入 Boat / Quartzware 状态**：位置、寿命、清洁、适配范围。
4. **建立三种开炉模式**：满载、时间窗、campaign。
5. **做回放验证**：拿历史队列回放，比较装载率、Q-time 和切换损失。
