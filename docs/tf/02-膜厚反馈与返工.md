# 膜厚反馈与返工回路

<div class="keyline" markdown>

**TF 的返工不是"重做一遍"，是"剥离重来，而且可能伤到下面已经做完的层"。** 这个代价决定了 TF 不该追求低返工率，该追求不把风险批量放大。

</div>

## 三种反馈

| 反馈 | 典型来源 | 敏感度 | 派工影响 |
|---|---|---|---|
| **厚度** | 膜厚量测（椭偏、XRR、方块电阻） | 高 | 直接调整沉积时间 / 功率 |
| **均匀性** | 多点量测 | 中 | 可能换腔体或换机台 |
| **应力** | 曲率法、XRD | 低但后果大 | 超限腔体降权 |

三者的处理节奏不一样：

- **厚度**是逐批反馈，可以直接调参数；
- **均匀性**是趋势反馈，通常按天或按腔体评估；
- **应力**是滞后反馈，等到下游暴露时已经晚了。

## 和 CMP 的 Run-to-Run 有什么不同

| 维度 | CMP | TF |
|---|---|---|
| 反馈对象 | 去除量，单变量为主 | 厚度 + 均匀性 + 应力，多变量 |
| 反馈延迟 | 短（磨完就量） | 中（可能等下一站才量） |
| 参数可调性 | 高（压力、转速、时间） | 中（时间、功率，部分 recipe 不可调） |
| 闭环稳定性 | 较好 | 较差，多变量耦合 |

所以 TF 不能照搬 CMP 的 R2R 做法。**CMP 可以激进调参，TF 要保守**——一次调过头，整批报废。

## Feedback Freshness

派工时必须知道"这个腔体上一次做这一层的结果，还有没有参考价值"：

| 情况 | freshness | 风险 |
|---|---|---|
| 同 recipe 连续跑 | 高 | 参数可靠 |
| 换 recipe 后又换回来 | 中 | 需确认中间有没有 PM |
| PM 或换靶之后 | **低** | 旧参数失效 |
| 长时间未跑该层 | 低 | 环境漂移 |

`feedback_age` 要按"事件"而不是"时间"计算：PM、换靶、部件更换都会重置它，而不是只过期若干天。

## 返工回路

### 三种处理

| 情况 | 处理 | 代价 |
|---|---|---|
| 厚度偏薄（可补） | 追加沉积 | 低，但要注意界面 |
| 厚度偏厚 | 剥离后重镀 | 中~高 |
| 应力超限 | 评估后续影响，可能放行 | 取决于层位置 |

**只有第一种是"补"，后两种都不是。** 派工系统如果把返工都当成"重跑一遍"，会严重低估资源占用。

### 返工的资源占用

| 占用项 | 说明 |
|---|---|
| 剥离工序 | 占用 etch / wet 产能 |
| 重新光刻 | 如果是图形化之后才发现，还要重做光刻 |
| 量测复检 | 返工批必须全检 |
| 腔体时间 | 返工批通常不能用关键层腔体 |

一条返工批的真实资源占用，可能是正常批的 2~3 倍。这个系数必须进模型，否则返工批会把计划整体挤爆。

## 防批量放大

TF 最怕的不是单片返工，是**同腔体连续多批一起偏**。

| 场景 | 机制 | 防护 |
|---|---|---|
| 靶材末期连续跑关键层 | 膜厚逐步漂移 | 末期限制关键层 |
| PM 后未 seasoning 就上量 | 头几批全偏 | 强制 seasoning 状态 |
| 参数调整后未验证 | 新参数未确认 | 调整后首批强制量测 |
| 同 recipe 长时间连跑 | 腔体积垢累积 | 设连续 run 上限，插入清洁 |

最后一条在 12 寸更要紧：连续跑同一 recipe 效率最高，但积垢会让膜厚慢慢漂，等量测发现时已经是一串批。

## 典型问题

### 问题 1：一次调参调过头

| 项 | 内容 |
|---|---|
| 现象 | 一批偏薄，调完参数后下一批全偏厚 |
| 根因 | 调整幅度按单点偏差给，没有阻尼 |
| 解法 | 调整带阻尼系数，且设单次最大调整量 |
| 指标 | parameter step size、overshoot count |

### 问题 2：返工批当成正常批排队

| 项 | 内容 |
|---|---|
| 现象 | 计划显示产能够，实际跑不完 |
| 根因 | 返工批按 1 倍资源占用计算 |
| 解法 | 返工批按 2~3 倍占用建模，单独计数 |
| 指标 | rework resource factor、实际 vs 计划偏差 |

### 问题 3：应力漂移无人认领

| 项 | 内容 |
|---|---|
| 现象 | 光刻套刻异常，查不出原因 |
| 根因 | 应力不在派工状态里，只在工艺监控里 |
| 解法 | 应力进 chamber 状态，超限降权 |
| 指标 | stress drift、下游异常归因中 TF 占比 |

## 字段清单

| 字段 | 说明 |
|---|---|
| `last_run_result` | 上一次同层同 recipe 的量测结果 |
| `feedback_age` | 距上次有效反馈的事件距离（PM / 换靶 / 换 recipe 均重置） |
| `is_rework` | 是否返工批 |
| `rework_factor` | 资源占用系数，默认 2~3 |
| `param_step_limit` | 单次允许的最大参数调整量 |
| `consecutive_run_count` | 同 recipe 连续运行批数 |

## 一条实操建议

**把"这一批有没有资格被派到这台机"和"派过去之后参数该用多少"分开处理。**

前者是派工问题，用 freshness 和状态判定；后者是工艺控制问题，交给 R2R 模块。混在一起做，派工系统会背上它不该背的工艺责任——出了膜厚问题，第一反应会变成"派工排错了"，而实际是参数调错了。
