# 指标冲突链

<div class="keyline" markdown>

**指标不是独立变量。** 它们被一条恒等式锁在一起，所以"同时改善所有指标"在数学上就不成立——除非你改了系统本身。

</div>

## 总纲：一条恒等式

<div class="keyline" markdown>

**平均周期时间 = 平均在制品 ÷ 平均产出率**

</div>

这就是 **Little's Law**。它在稳态下恒成立，不依赖任何调度算法。

推论很硬：

- 想提吞吐（分母↑），要么加产能，要么加在制品（分子↑）
- 想压周期时间（左边↓），要么压在制品，要么提产出
- **三个量只能动两个**

派工项目里所有"既要又要"的承诺，都要先过这一关。

## 四条冲突链

<div class="grid cards" markdown>

-   :material-arrow-up-bold-box-outline:{ .lg .middle } __① 吞吐 ↑ → 周期 ↑__

    ---

    提吞吐靠加在制品，在制品一多，排队时间变长。

    **传导**：投料加密 → 队列变长 → 排队时间↑ → CT↑

-   :material-arrow-down-bold-box-outline:{ .lg .middle } __② 利用率 ↑ → 换线 ↑__

    ---

    把机台塞满，意味着更多小批量、更多不同配方。

    **传导**：填谷 → 换线次数↑ → 整定时间↑ → 长期有效产能↓

-   :material-swap-horizontal-bold:{ .lg .middle } __③ 周期 ↓ → 换线 ↑__

    ---

    压周期通常靠小批量快跑。

    **传导**：批量↓ → 同配方连续加工机会↓ → 换线↑

-   :material-flash-alert:{ .lg .middle } __④ 加急 ↑ → 普通批 ↑__

    ---

    加急批的提速，是从普通批那里借来的。

    **传导**：插队 → 普通批等待↑ → 普通批交付风险↑

</div>

## 为什么这几条链必须一起看

单看任何一条，结论都是"这个指标变差了"。放在一起才看得出：

> 指标恶化往往不是派工做错了，而是**你压的那个指标，代价转移到了另一个指标上**。

所以派工项目的验收必须写清：主指标改善多少，代价指标允许恶化多少。只写"提升吞吐 X%"，等于默许系统把周期时间干掉。

## 三层指标

| 层 | 数量 | 用途 | 能不能用来考核 |
|---|---|---|---|
| **主指标** | 1 个 | 项目验收的唯一判据 | 能，但要看长期 |
| **约束指标** | 2~3 个 | 不允许突破的红线 | 能，作为否决项 |
| **观测指标** | 若干 | 定位问题、诊断原因 | **不能** |

!!! danger "最常见的翻车方式"
    把观测指标拉进考核。比如把"机台利用率"写进班组 KPI，结果机台为了刷利用率去接不该接的活，白空间没减少，反而多了换线。

## 主指标怎么选

按区域所处阶段选，不要照搬：

| 阶段 | 主指标 | 理由 |
|---|---|---|
| 产能爬坡 | 产出片数 | 交付压力最大，周期可以忍 |
| 稳定量产 | 周期时间 / 准时交付 | 产出够了，拼的是响应速度 |
| 多品种小批量 | 准时交付率 | 主指标会掩盖品种间的失衡 |

## 测量的三个陷阱

1. **基线不可比。** 公开文献的改善幅度横跨十几年、不同厂型、不同基线，**只能当量级参考**。
2. **窗口太短。** 派工系统的效果有滞后，两周的数据说明不了问题。
3. **没设对照组。** 同一时间段、同一条线、同一产品组合的前后对比，才叫基线。
