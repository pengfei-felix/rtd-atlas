# 指标冲突链

<div class="keyline" markdown>

**派工项目最怕“所有指标都要变好”。** 吞吐、WIP、周期、Q-time、换线、搬送不是独立旋钮。你压下一个，另一个往往会弹起来。专业的指标体系不是许愿清单，而是取舍协议。

</div>

## 总纲：先过 Little's Law

<div class="keyline" markdown>

**平均周期时间 = 平均在制品 ÷ 平均产出率**

</div>

这条式子在稳态下恒成立，不依赖派工算法。它给 RTD 项目划了一条硬边界：

- 想提吞吐，要么释放瓶颈产能，要么允许更多 WIP；
- 想压周期，要么压 WIP，要么提产出；
- 想 WIP、CT、TH 同时变好，必须真的改变系统能力，而不是只改排序。

<div class="rtd-strip" markdown>

<span>验收原则</span> 一个主指标 + 两三个约束指标 + 若干观测指标  
<span>禁止动作</span> 把观测指标直接写成 KPI

</div>

## 五条常见冲突链

<div class="grid cards" markdown>

-   :material-arrow-up-bold-box-outline:{ .lg .middle } __吞吐 ↑ → WIP ↑ → CT ↑__

    ---

    投料加密或瓶颈前缓冲增加，会推高在制品。若瓶颈能力没同步提高，周期时间会变长。

-   :material-timer-sand:{ .lg .middle } __CT ↓ → Setup ↑__

    ---

    小批量快跑能压单批等待，但会打碎 campaign，换线次数增加。

-   :material-cog-transfer:{ .lg .middle } __利用率 ↑ → 灵活性 ↓__

    ---

    机台被塞满后，异常和 Hot Lot 没有插入空间，系统抗扰动能力下降。

-   :material-flash-alert:{ .lg .middle } __Hot Lot ↑ → 普通批风险 ↑__

    ---

    加急批提速不是凭空来的，通常来自普通批等待时间增加。

-   :material-truck-fast:{ .lg .middle } __资源前置 ↑ → Move ↑__

    ---

    提前搬 Reticle / Boat / Pad 能减少白空间，但会增加搬送次数和 AMHS 压力。

</div>

## 三层指标结构

| 层级 | 数量 | 用途 | 例子 |
|---|---|---|---|
| **主指标** | 1 个 | 验收最终目标 | 有效产出、CT、OTD |
| **约束指标** | 2–3 个 | 防止用副作用换主指标 | Q-time 违规、WIP 上限、返工率 |
| **观测指标** | 若干 | 诊断原因，不直接考核 | 利用率、白空间、换线、move 次数 |

判断标准：如果一个指标变好后，现场会为了刷它做错误动作，它就不适合直接考核。

## 主指标怎么选

| 场景 | 主指标 | 约束指标 | 不建议主考核 |
|---|---|---|---|
| 新厂爬坡 | 有效产出 | Q-time、返工、关键资源 move | CT |
| 产能瓶颈 | 瓶颈有效产出 | WIP、setup loss、Scrap | 全区平均利用率 |
| 多品种小批量 | OTD / 交付达成 | WIP、Hot Lot 影响面 | 单机利用率 |
| 周期压缩 | CT / X-factor | 吞吐不下降、Q-time 不恶化 | 队列长度单点值 |
| 质量敏感 | 返工率 / 稳定性 | 产出下限、CT 上限 | 短期 throughput |

没有“通用最优指标”。阶段变了，主指标也要变。

## 指标口径表

| 指标 | 分子 | 分母 / 口径 | 注意 |
|---|---|---|---|
| Throughput | 完成 wafer / lot 数 | 固定窗口，如 day / shift | 要区分 gross 和 good wafer |
| Effective output | 扣除返工/报废后的有效产出 | 固定窗口 | 比表面 throughput 更真实 |
| CT | lot 完工时间 - release 时间 | 同产品族 / 同 route 比较 | mix 变化会污染结论 |
| WIP | 在制 lot / wafer | 按区域、route step 或全厂 | 不同粒度不能混算 |
| Q-time violation | 超窗次数 / 批数 | 以窗口启动后的 Lot 为分母 | 要分严重度和归因 |
| Setup loss | setup 时间 | 可用生产时间 | 必须区分计划内/计划外 |
| White space | 可生产但未生产时间 | tool / chamber 可用时间 | 要分无料、无资源、无人员 |
| Move count | 资源或 Lot 搬送次数 | 单位时间 / 单位产出 | 不能脱离 AMHS 容量看 |

没有分母的指标不要上报告。没有归因的指标不要做决策。

## 基线实验设计

### 1. 时间窗口

至少覆盖一个完整生产节奏周期。短窗口容易把某次异常当成系统效果。

| 数据窗口 | 可做什么 | 不适合做什么 |
|---|---|---|
| 1–2 天 | 看功能是否生效 | 判断收益 |
| 1–2 周 | 看趋势和异常 | 签收益结论 |
| 4 周以上 | 做相对基线 | 初步验收 |
| 8–12 周 | 看稳定收益 | 合同级对赌 |

### 2. 对照方式

| 方法 | 优点 | 风险 |
|---|---|---|
| 前后对比 | 最容易做 | mix、投料、设备状态变化会污染 |
| 分区 A/B | 对照清楚 | 现场难保证条件一致 |
| 历史回放 | 安全、可重复 | 依赖事件数据完整性 |
| 影子模式 | 接近真实，不干扰生产 | 需要完整日志和解释机制 |

RTD 项目最推荐：**历史回放 → 影子模式 → 小范围接管 → 扩区上线**。

### 3. 异常日处理

要提前写清哪些天剔除，不能事后挑数据。

可剔除场景：

- 全厂性停电 / 厂务异常；
- 关键设备长时间非计划停机；
- 大规模 hold / release 异常；
- route / recipe 大版本切换；
- 数据采集缺失。

剔除要保留清单，不能只留结论。

## 指标归因树

```text
主指标没改善
├─ 瓶颈没变：优化错区域
├─ 瓶颈变了：收益被新瓶颈吃掉
├─ WIP 不足：瓶颈饥饿
├─ WIP 过高：排队时间抵消收益
├─ setup 增加：小批量/频繁切换吃掉产能
├─ 辅助资源不到位：机台等资源
└─ Q-time / Hot Lot 插队：局部救火扰乱全局
```

这棵树比“指标没达标”有用。它能告诉你下一步该改规则、改投料，还是改资源约束。

## 验收写法

不要写：

> RTD 上线后提升产能 5%。

建议写：

> 在产品 mix、投料节奏和设备可用率可比的 8 周窗口内，以 Litho 瓶颈机群为对象，good wafer throughput 较基线提升 X%；同时 Q-time violation 不高于基线 +Y%，Reticle move 不高于基线 +Z%。

关键不是数字多漂亮，而是口径能被复算。
