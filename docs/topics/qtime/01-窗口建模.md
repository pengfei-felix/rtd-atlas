# Q-time 窗口建模

<div class="keyline" markdown>

**Q-time 不是倒计时字段，而是跨工序容量约束。** 只看单个窗口的剩余时间，会漏掉后续窗口、下游能力和搬送长尾。

</div>

## 单窗口模型

| 字段 | 说明 |
|---|---|
| window_id | 窗口唯一 ID |
| start_event | 起点事件，如 clean out |
| end_event | 终点事件，如 etch in |
| max_duration | 最大允许时间 |
| yellow_threshold | 提前预警阈值 |
| red_threshold | 强制抢救阈值 |
| current_state | green / yellow / red / expired |
| owner_area | 主要责任区域 |

## 走廊模型

```text
Window 1: Clean → Etch
Window 2: Etch → Strip
Window 3: Strip → Metrology
```

走廊模型要看的是：当前派工会不会让后续窗口变危险。

## 状态分级

| 状态 | 含义 | 动作 |
|---|---|---|
| Green | 安全 | 正常优化 setup / load |
| Yellow | 可提前干预 | 预约资源、预搬送、入口限流 |
| Red | 剩余选择很少 | 硬抢救，但记录影响面 |
| Expired | 已违规 | 停止美化，做归因和防复发 |

## 建模误区

| 误区 | 后果 |
|---|---|
| 起点定义不统一 | 同一 Lot 不同系统算出不同剩余时间 |
| 只看当前窗口 | 后续窗口被打爆 |
| 不看 AMHS ETA | 理论可派，实际到不了 |
| 不看下游预约 | 上游完成后继续堵 |
| 红区才处理 | 只能半炉、插队、人工救火 |
